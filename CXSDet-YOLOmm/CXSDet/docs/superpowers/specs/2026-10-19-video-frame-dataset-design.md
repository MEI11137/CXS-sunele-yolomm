# 视频抽帧与待划分数据集设计

## 1. 目标

管理员在导入视频执行检测时，可以选择同时生成一个可命名的数据集。系统按“每隔 N 个原始视频帧抽取一张”的规则保存原始图片，使用独立可选的已发布模型生成 YOLO 初始标签，并把结果保存为待人工筛选、待人工划分的数据集。

同一套待划分工作流也替换现有图片检测反馈数据集的错误划分方式。系统不再把全部反馈样本直接放入 `train`，也不再复制第一条训练样本充当验证样本。

本功能完成并验证后，需要交付一份 GitHub Release 说明草稿。Release 版本号由后续 Git 标签决定；未经用户确认不得自动创建或发布远程 Release。

## 2. 权限与入口

- “同时生成数据集”仅对管理员显示和开放。
- 入口位于现有视频检测表单，不新增独立上传页面。
- 开关默认关闭。关闭时，现有视频检测行为保持不变。
- 打开后显示数据集生成配置，并随视频检测请求一起提交。
- 待划分数据集在管理员“数据集管理”页面中管理。

## 3. 视频检测表单

### 3.1 公共字段

打开“同时生成数据集”后显示：

- 数据集名称：必填，必须在正式数据集和待划分数据集中全局唯一。
- 数据集描述：选填。
- 数据集模式：`单模态` 或 `多模态`。
- 抽帧间隔：正整数 N；N=1 表示每帧抽取，N=2 表示抽取第 1、3、5、7……帧。
- 标注模型：必填，默认使用视频检测模型，但允许管理员重新选择。
- 标签置信度阈值：默认继承视频检测阈值，允许单独调整。

选定视频并读取总帧数后，页面显示预计抽取数量。预计值用于提示，不设置任意的固定样本数上限。

### 3.2 模型兼容规则

- 单模态数据集只显示已发布的单模态模型。
- 多模态数据集只显示与所选第二模态匹配的已发布多模态模型。
- 视频检测模型与数据集模式、第二模态兼容时，标注模型默认选中视频检测模型。
- 视频检测模型不兼容时，标注模型不自动选中，管理员必须选择兼容模型。
- 后端重复执行相同兼容校验，不能只依赖前端过滤。

### 3.3 多模态附加字段

选择多模态后额外显示：

- 第二模态类型，例如 `thermal`。
- 第二模态视频文件。
- 第二模态时间偏移，单位秒，默认 0；正负值都允许。

RGB 视频为主时间轴和抽帧基准。系统不要求两个视频具有完全相同的帧率、帧数或时长。

## 4. 后台处理流程

### 4.1 任务隔离

视频检测结果和数据集生成结果分别记录状态：

- 视频检测成功但数据集生成失败时，视频记录仍为成功。
- 数据集生成失败时保存公开可读的失败原因和原始参数，管理员可以从视频记录重新生成。
- 失败草稿允许使用原 ID、名称和保存参数原地重试；已成功生成的草稿不能重试或被覆盖。

### 4.2 抽帧

- 以 RGB 原视频的零基帧序号为准，从第 0 帧开始，每隔 N 帧选取一个样本。
- 保存无检测框、无文字覆盖的原始帧。
- 文件名使用稳定的样本键，包含视频记录 ID 和原始帧号，避免并发任务冲突。
- 每个样本记录来源视频记录、原始帧号、时间戳、抽帧间隔和创建时间。

### 4.3 多模态宽松配对

对每个已选 RGB 帧：

1. 计算 RGB 时间戳。
2. 应用管理员设置的第二模态时间偏移。
3. 在第二模态视频中定位时间最接近的帧。
4. 目标帧读取失败时，在邻近帧范围内搜索最近的可读帧。
5. 找到后，以同一样本键保存 RGB、第二模态图片和一份共享标签。
6. 仍无法配对时保留 RGB 样本，标记为 `missing_secondary`，不静默删除，也不伪造或复制无关帧。

任务结果记录成功配对数量、缺失数量、每个样本的时间差和最大配对误差。缺失样本可以在人工划分页面补传对应模态图片或标记排除。

### 4.4 自动初始标签

- 标注模型独立于视频检测模型运行；两者相同且输入模式兼容时允许复用推理结果，避免重复推理。
- 单模态模型读取 RGB 图片。
- 多模态模型读取配对的 RGB 和第二模态图片；缺少第二模态的样本不运行多模态标注，状态标记为待修复。
- 通过标签置信度阈值的检测框转换为标准 YOLO 标签：`class_id center_x center_y width height`，坐标归一化到 0 到 1。
- 未检测到目标时仍生成同名空标签文件，作为合法背景样本。
- 原始图片不绘制检测框。
- 数据集记录标注模型 ID、模型名称、类别映射和置信度阈值。
- 视频抽帧过程不自动调用视觉大模型核验。视觉大模型仅保留在现有图片检测复核流程中。

## 5. 待划分数据模型与存储

现有 `datasets` 表要求 ZIP 存储字段非空，因此不使用空对象或占位 ZIP 表示生成中的数据集。新增职责明确的草稿表：

### 5.1 `dataset_drafts`

保存：

- 草稿 ID、名称、描述和创建者。
- 来源类型：`video` 或 `feedback`。
- 来源视频记录 ID 或来源反馈数据集 ID。
- 数据集模式、主模态和第二模态。
- 工作流状态：`generating`、`draft`、`failed`、`finalized`。
- 抽帧、模型、置信度、时间偏移和配对统计元数据。
- 可公开展示的失败原因、创建时间和完成时间。

### 5.2 `dataset_draft_samples`

每行代表一个不可拆分的训练样本，保存：

- 草稿 ID 和稳定样本键。
- RGB 图片存储位置。
- 第二模态图片存储位置和来源；单模态时为空。
- YOLO 标签文件存储位置以及结构化标注快照。
- 来源帧号、两个模态时间戳和配对误差。
- 配对状态和修复信息。
- 人工分配：`unassigned`、`train`、`val`、`test` 或 `excluded`。

视频抽出的图片和标签以独立对象保存，便于人工页面按样本预览和修复。图片检测反馈样本可以引用已有原图对象；只有最终生成训练 ZIP 时才复制内容。

正式 `datasets` 列表接口返回正式数据集与未完成草稿的统一视图，但 `finalized` 草稿不重复显示。模型训练接口仍只接受 `datasets.status == APPROVED` 的正式数据集。

## 6. 人工筛选与划分

### 6.1 列表状态

数据集管理页面显示：

- 生成中
- 待划分
- 可训练
- 生成失败

失败任务显示原因和重试入口。可训练状态继续沿用现有正式数据集展示和训练选择逻辑。

### 6.2 样本页面

- 卡片或表格显示 RGB 预览、第二模态预览、标签框数量、类别、来源帧号和配对状态。
- 支持按未分配、训练集、验证集、测试集、缺失模态和已排除筛选。
- 支持多选样本，批量分配到 `train`、`val`、`test`、移回 `unassigned` 或标记 `excluded`。
- 多模态图片与共享标签作为一个样本整体操作，不能拆开分配。
- 缺失第二模态时允许上传替换图片；补传后重新计算配对状态，并可使用同一标注模型重新生成该样本标签。
- 标签为空是合法状态；标签文件缺失是错误状态。

### 6.3 标记为可训练

只有以下条件全部满足时才能完成：

- 不存在 `unassigned` 样本。
- `train` 和 `val` 至少各有一个未排除的有效样本。
- `test` 可以为空。
- 所有未排除的多模态样本配对完整。
- 所有未排除样本都有同名标签文件，标签内容为空时视为背景样本。
- 类别 ID 均在标注模型类别映射范围内。

完成时按人工分配生成标准结构：

```text
dataset/
├─ images/train/
├─ images/val/
├─ images/test/             # 有测试样本时生成
├─ images_<X>/train/        # 多模态时生成
├─ images_<X>/val/
├─ images_<X>/test/         # 有测试样本时生成
├─ labels/train/
├─ labels/val/
├─ labels/test/             # 有测试样本时生成
├─ data.yaml
└─ manifest.json
```

服务端重新验证图片、标签和多模态配对，生成 ZIP，上传文件服务，并在 `datasets` 中创建与草稿同 ID、同名称的正式记录，状态设为 `APPROVED`。草稿状态改为 `finalized` 并保留溯源信息，但不在数据集列表重复显示。

## 7. 图片检测反馈数据集调整

- AI 大模型复核仍只输出复核意见，不直接生成最终标签。
- 只有人工确认后的 `corrected_annotations` 能进入反馈样本池。
- “生成反馈数据集版本”改为创建 `feedback` 来源的待划分草稿。
- 每条反馈样本生成或引用原图、配对模态图片和人工确认后的 YOLO 标签。
- 不再把全部样本直接写入 `train`。
- 不再复制第一条训练样本到 `val`。
- 反馈草稿与视频草稿共用同一人工筛选、修复、划分和最终验证流程。

## 8. API 边界

后端新增或扩展以下能力，具体 URL 在实现计划中按现有路由风格确定：

- 视频检测提交：接收可选数据集生成配置和第二模态视频。
- 视频进度：返回独立的数据集生成状态、草稿 ID 和统计。
- 草稿列表与详情：分页读取草稿及样本。
- 草稿样本批量分配：原子更新所选样本的人工分配。
- 缺失模态修复：上传单个样本的第二模态图片并重新标注。
- 失败草稿重试：清理无效的局部状态，使用保存的来源和参数重新执行同一草稿任务。
- 草稿最终化：验证并生成正式可训练数据集。
- 反馈版本生成：返回待划分草稿信息，不再直接返回可训练数据集。

所有写接口仅允许管理员。批量分配请求必须验证样本全部属于同一草稿，并在一个数据库事务中更新。

## 9. 错误处理与清理

- 名称冲突、无效间隔、模态不匹配和缺少第二视频在启动后台任务前返回明确错误。
- 视频、模型或文件服务错误不得把成功的视频检测错误标记为失败。
- 数据集生成发生异常时，草稿状态设为 `failed`，保存安全的错误摘要，不向前端泄露凭据或内部路径。
- 部分上传成功后失败的对象记录在任务清单中，重试时复用有效对象；删除草稿时统一清理仅由该草稿拥有的对象。
- 最终化失败不改变草稿分配，管理员修复问题后可以重试。
- 正式 ZIP 上传成功但数据库写入失败时，删除新上传的 ZIP，避免孤儿文件。

## 10. 测试与验收

### 10.1 后端单元测试

- N=1、N=2 和任意正整数 N 的准确抽帧序列。
- 非法间隔拒绝。
- 单模态和多模态模型过滤及后端兼容校验。
- 多模态时间偏移、最近时间帧、邻近可读帧搜索和缺失保留。
- YOLO 坐标归一化、类别 ID、空标签和越界框处理。
- 草稿名称与正式数据集名称全局唯一。
- 批量分配的权限、所属关系、事务原子性和合法状态。
- 最终化对未分配、缺失模态、缺失标签、空 train、空 val 和可选 test 的校验。
- 单模态、多模态标准 ZIP 与 `data.yaml` 验证。
- 图片反馈导出不再制造重复验证样本。

### 10.2 路由与数据库测试

- 旧数据库迁移后保留所有现有数据。
- 普通用户看不到或无法调用草稿写接口。
- 视频成功、草稿失败时两个状态互不污染。
- 重试不会覆盖成功草稿或产生同名正式数据集。
- 最终化失败回滚数据库并清理新 ZIP。

### 10.3 前端验证

- 开关关闭时原视频检测表单行为不变。
- 单模态与多模态字段按选择正确显示。
- 标注模型默认值和兼容过滤正确。
- 预计抽帧数量正确。
- 样本筛选、多选、批量分配、排除和缺失模态修复正确。
- 待划分数据集不会出现在模型训练选择框中。
- 前端类型检查和生产构建通过。

### 10.4 端到端验收

- 使用短单模态测试视频按 N=1、N=2 分别生成草稿，样本数量和标签配对正确。
- 使用帧率或时长不同的 RGB 与第二模态短视频生成草稿，确认宽松时间配对和缺失样本保留。
- 人工完成 train/val 分配后生成 ZIP，并通过现有训练数据集验证器。
- 图片检测人工确认样本生成反馈草稿，确认 train/val 中不存在自动复制的重复样本。

## 11. Release 说明交付

实现完成并通过验收后，生成 GitHub Release 说明草稿，至少包含：

- 视频检测同步抽帧和自动初始标签。
- 单模态与宽松时间配对的多模态视频支持。
- 独立标注模型选择及兼容规则。
- 待划分数据集与人工批量 train/val/test 分配。
- 缺失模态修复、样本排除和可训练校验。
- 图片反馈数据集不再复制验证样本。
- 数据库迁移、兼容性、操作入口和已知限制。

Release 说明引用实际测试结果，不宣称未执行的端到端验证。远程发布、打标签和推送均需要用户另行确认。
