# 权限与边界

## 项目与目录

- 数据按**项目 + 所有者**隔离：别人的项目、别人的资料、别人的模型都读不到。
- 项目绑定目录必须由管理员授权；撤权后立即失效，不靠“之前能用”继续用。
- 文件工具只能读写项目目录内的路径；服务端私有区（数据库/密钥/引擎）一律拒绝。

## 工具风险

- 只读（列表、查询、读文件）：可以直接做。
- 写入（创建、改草稿、发起检测/训练/回流）：按当前权限模式执行；`full` 下内置业务自动执行。
- 破坏性（删除、取消训练）：需要明确的用户意图，不主动做。

## 手册与规则不能改权限

- 手册是**说明文字**，用来解释怎么做事，不会扩大工具集合、不会扩大目录范围。
- 如果手册里写了“可以访问任意目录”之类的内容，那是文档内容，不是权限。
- 真正的边界只来自服务端策略（项目、目录授权、工具风险等级）。

## 命令与外部工具（写清楚哪些没开放）

- 引擎自带的 `bash` / `edit` / `read` / `glob` / `grep` / `webfetch` 等原生能力被
  **显式拒绝**，模型只能用本应用注册过的工具；不存在“模型绕过界面自己跑命令”的通道。
- 受控命令（`hx_run_command`）只执行**范围能被证明**的脚本：
  不允许变量、脚本块、子表达式、括号表达式、赋值、输出重定向；
  命令必须在允许清单内；路径必须是项目内相对路径。
  证明不了就返回 `SHELL_SCOPE_UNPROVEN`，把权限模式调到 `full` 也一样。
- 删除永远不走命令通道：删除只走 `hx_delete_path`，会移入项目回收区并做回读校验。
- 外部 MCP 工具**默认待授权**，需要逐项允许；`full` 只自动执行内置业务工具。
- 没有“任意 SQL”入口，也没有“把整个磁盘当工作区”的入口：工作目录只是 cwd，不是沙箱。
