# 光伏质检闭环工作流

这个项目做的是一条**可追溯的质检闭环**，不是“上传一张图给个结论”。

## 闭环九步

1. 导入数据集（ZIP 或项目目录），逐样本校验后登记版本。
2. 训练模型（CPU，参数先校验；单机同一时间只允许一次训练）。
3. 发布模型到**本项目**；发布只取代本项目里旧的已发布模型，不碰其他项目。
4. 检测：单张、批量或目录巡检，结果写入识别记录。
5. AI 核查（可选）：用本人当前连接看图给参考结论，**仅供参考**。
6. 人工复核：选择/移动/角点改框/画框/删除/撤销，保存草稿后再提交结论。
7. 反馈：把“已确认且未回流”的记录加入反馈池。
8. 数据回流：回原修订（替换同一张图的标注）或另建数据集（追加新图）。
9. 新版本数据集 → 增量训练 → 父子指标对比 → 再发布。

## 谁做决定

- **模型可以**：编排上面的步骤、发起检测/训练/回流、查询状态与日志。
- **必须由人做**：最终的人工结论（确认/驳回）、模型发布、训练参数确认、凭据与授权。
- 训练/检测是**服务端后台任务**，模型只负责发起或查询，不在对话里自己跑循环。

## 数据放在哪

- 业务产物（上传、结果图、数据集、训练日志与权重）都在**项目绑定目录**里。
- 服务端私有区（数据库、密钥、引擎）在 `var/`，业务文件不能写进去。

## 这个版本不做什么

- **没有视频与实时巡检**：只做静态图片（单张上传，或按目录批量巡检）。摄像头/RTSP
  这类流式输入没有接进网页，也没有对应工具；推理引擎自带的流式能力不会被网页直接调用。
- **没有公网发布**：服务只监听本机回环地址，远程访问需要自己搭一层受控入口。
- **没有任意 SQL / 任意命令**：命令通道只跑可证明范围的脚本，数据库只走业务接口。
