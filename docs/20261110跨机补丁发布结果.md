## 1. 代码变更（3 个文件）

| 文件 | 变更 |
| --- | --- |
| `frontend/src/components/ZoomableImage.vue` | **新增**：检测结果图的框内查看器（固定框适应 / 滚轮指针中心缩放 / 按钮缩放 / 100% / 拖动平移），复用 `lib/geometry` 的 `fitView / zoomAt / panBy / toImage` |

| `backend/services/connections.py` | 探测请求 `max_tokens`：chat `1 → 128`、vision `8 → 1024`、tools `16 → 512`；真实视觉挑战、真实 `tool_calls`、认证判定与错误证据逻辑**未改**，没有把 HTTP 200 强行判成能力通过 |

交接给的组件草案在两处按实测补了局部修正（均在本组件内，未改全局 geometry）：

1. **换图可靠性**：草案只在 `@load` 里清 `loading`，同一位置换结果图会沿用旧尺寸；先失败时 `<img>` 已被 `v-if` 移出，再没有元素触发 load。现用 `watch(src)` 重置加载/失败/尺寸/视角/拖动态，并给 `<img>` 加 `:key="src"` 强制重建。
2. **`MIN_SCALE` 边界**：`fitView` 把比例夹到 `0.1`，4000×3000 在窄屏（≈380px 宽）需要 ≈`0.07`，被夹到 `0.1` 会横向溢出。现在 fit 时若精确适应比例小于 `fitView` 结果则用它兜底，缩放下限跟随该比例，并避免 `zoomAt` 把比例抬回 `0.1` 造成“缩小反而变大”。
