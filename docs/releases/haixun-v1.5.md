## 此次修复

| 真实用户问题 | v1.5 的行为 |
| --- | --- |
| 普通评委账号不能改变权限模式 | 本人会话三档权限对所有角色开放，公网网关放行并交由后端核对会话归属。权限档位不扩大可访问的项目或目录。 |
| 工具执行后对话冗长 | 工具过程及中间执行说明默认折叠；最终回答继续显示并独立刷新。只展示实际执行信息，不展示模型内部 reasoning。 |
| 多次写入必须先确认计划、计划版本不断增长 | OpenCode 自行安排步骤，不再暴露或要求 propose_plan；兼容旧调用但不创建版本。缺少必要参数通过普通对话询问；删除、覆盖与人工结论保留具体确认。 |
| 本地图片登记后不能检测 | image 登记写入正确类型；旧 project_file 图片通过受保护文件网关核验真实图片内容后可继续检测，其他文件不会被视为图片。 |
| 闭环工具笼统报连接失败 | 准备阶段忽略已失去模型业务行的残留索引；桥接区分业务错误、HTTP、超时和连接异常，保留未知执行状态，不自动重试写入或计费操作。 |
| 后台运行时 Agent 尝试 Shell 睡眠 | 工具明确返回后台接管与自动通知要求；无需在对话中等待，后台结果会直接发送并打开复核页。 |

## 已知限制与更新

真实日志中的所有 HTTP 原因未被原版记录，因此不能把每次“工具连接失败”都认定为同一个故障；v1.5 修复了可复现的残留索引异常，并补齐具体错误码。模型上游限流、繁忙或网络异常仍可能发生，应按具体错误核实。

原 v1.4 曾验证特定配置的三张图片闭环，没有覆盖本次日志中的本地登记类型、公网权限切换及残留模型索引组合；因此此前验收不能代表全部用户路径已通过。

更新前备份服务器自己的数据库、工作目录、密钥及演示配置。获取本版本源码后，在 web-haixun 执行 `npm ci`、`npm run build`，停止并重启后端及演示服务，再刷新浏览器；只覆盖前端不会修复后端权限和文件类型问题。原工作目录保持原路径时不必迁移数据。

GitHub 分支包含前端、后端、业务服务、部署脚本、测试与文档的完整源码；不包含个人 Key、数据库、原始数据、PT 权重、node_modules、Python 环境、引擎二进制或预构建 dist。保留服务器原有依赖、数据和账号，不能用空白新库覆盖原数据库。
