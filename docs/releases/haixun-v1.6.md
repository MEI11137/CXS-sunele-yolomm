## 此次修复

| 真实用户问题 | v1.6 的行为 |
| --- | --- |
| 在聊天里让内嵌 Agent 用本人模型连接做 AI 核查时，工具返回 `AGENT_UNAUTHENTICATED`，提示无法确定当前用户 | 私有 MCP 桥在完成令牌校验后写回站点用户身份，聊天内 Agent 与页面按钮使用同一本人连接；伪造或非本机令牌仍拒绝，不改变账号隔离与项目边界。 |
| 复核请求偶发 502“大模型网络异常或请求超时” | 复核单次模型调用使用独立超时（复核 180 秒、改进建议 120 秒），聊天默认超时不变，仍不自动重试计费请求。 |
| 批量复核失败时直接把上游原文或异常名展示给用户 | Agent 错误按安全白名单与凭据脱敏输出；未识别的错误只给固定提示，不泄露密钥、请求头和上游正文。 |
| 引擎内部压缩摘要以普通助手消息出现在对话里 | 按引擎结构化元数据识别内部压缩/摘要消息，不保存为普通回答，也不参与最终答复判定；历史已入库摘要标记 `internal_context` 后从消息 API 和前端隐藏，原文保留供审计。 |
| 完全访问模式下删除、恢复、已有文件修改等内置业务仍逐项生成确认卡 | 已授权的平台内置业务按会话策略直接执行并记录自动决策来源，不再逐项出卡；外部 MCP、新授权、越界或无法证明范围的命令明确拒绝并提示替代方式。最终人工复核结论仍必须由本人在复核页提交。 |
| 系统提示与权限选择器仍写旧的“删除、已有文件修改仍需批准” | 提示与界面说明同步为上述行为，并明确删除/修改命令应单独执行、返回后用独立读取工具核验。 |

## 未验证与已知限制

- 批量 3 张图片串行核查时，私有 MCP relay 的 90 秒上限仍短于单次视觉请求的 180 秒超时，长批量仍可能超时；本版不宣称该风险已解决。
- 未运行 GPU 训练，不宣称训练通过；公网服务器完整部署、外部通道与浏览器实测未在本版执行。
- 前端 34/34 测试、类型检查与生产构建已在宿主本机通过；GitHub 源码不带预构建 `dist`，远程演示前须在服务器执行 `npm ci`、`npm run build`。
- 模型上游限流、繁忙或网络异常仍可能发生；仍按具体错误核实，不把单次成功写成全部路径通过。

## 交付边界与更新

- 源码不包含个人 API Key、数据库、业务数据、测试记录、模型权重、训练数据、`node_modules`、Python 环境、引擎二进制或预构建前端产物。
- 已有服务器更新前，先停服务并备份该服务器自己的数据库、密钥、演示配置、项目目录与工作目录；本版不重命名、不迁移服务器既有工作目录，也不清空或替换其账号、API 连接和运行数据。
- WorkBuddy Dispatcher 属于独立开发工具，不包含在网站源码包中，也不写入任何 token、本机私有配置或调试地址。
- 获取本版本源码后：在 `CXSDet-YOLOmm/CXSDet/web-haixun` 执行 `npm ci`、`npm run build`，停止并重启后端与演示服务，再刷新浏览器。只覆盖前端不会修复后端身份、超时与脱敏问题。
- 发布分支 `release/haixun-v1.6.0` 已由 root 创建；最终发布状态以 GitHub 分支/标签为准，本文件不提前宣称已上传成功。
