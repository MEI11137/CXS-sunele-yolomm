## 1. 前置修复（按评审要求）

### 1.1 受限权重加载：从“import 后判断”改为“导入前固定符号表”

- 上一版仍会先 `_import_symbol(ref)` 再判断是不是 `nn.Module` 子类——不可信 checkpoint
  可以通过声明任意模块名触发 import。现在 `ALLOWED_SYMBOLS` 是**代码里写死的审核表**
  （真实 best.pt 的 17 个引用 + 按已支持架构人工补充的常见结构类）；
  表外引用**连 import 都不会发生**，直接 `WEIGHT_UNTRUSTED` 并提示如何增加审核支持。
- 仍然使用 PyTorch 原生 `get_unsafe_globals_in_checkpoint` + `safe_globals` +
  `weights_only=True`；没有裸 pickle 回退；`torch.storage._load_from_bytes` 在禁止列表里。
- 证据：`test_unreviewed_symbol_is_not_imported` 在临时目录放一个“被 import 就写 marker”的模块，
  构造引用它的 checkpoint，断言加载被拒、marker 不存在、`sys.modules` 里没有该模块。
  真实 best.pt 仍可 `inspect_weight`（2 类）与 CPU 推理。

### 1.2 检测记录的类别名：目标数据集口径

- 旧 `class_labels` 把 `native[source]` 放到 target 键上，映射到「单一热斑」后界面仍显示
  `single_hotspot`。现在按 `class_map` 反查**目标数据集**类别名；未绑定数据集才回落到模型自带名称。
- 记录里保留 `native_class_id` / `native_class_name` 供追溯；写入与读取（列表/详情/队列）
  都走同一解析，旧记录也能正确显示。
- 证据：`test_target_dataset_class_names_follow_mapping` 用非恒等映射（0→1、1→0）+
  中文类别「鸟粪污渍/裂纹」，断言展示名与 `class_summary` 都是目标类别、native 名单独保留。

## 2. 人工复核

### 2.1 数据模型（迁移 v9）

- `review_versions`：每条记录可有多版；`draft` 可反复保存，`confirmed` / `rejected` 不可变。
  唯一约束：`(project_id, detection_id, version)`、每人一条 draft、`(project_id, request_key)`。
- `record_feedback`：只认“已确认且未回流的版本”，`UNIQUE(detection_id, review_version_id)`。
- `detections` 增加 `deleted_at/deleted_by/flow_id`；`datasets` 增加父版本、`kind`、种子、
  划分策略、request_key、manifest/export 相对路径。

### 2.2 草稿 / 提交 / 驳回 / 重开

- 草稿基准是**最近一次已提交版本**（草稿不算）；提交/驳回用 `base_version` 做乐观锁，
  冲突返回 409 与当前版本，**草稿保留**；同一 `request_key` 幂等，不反复涨版本。
- 驳回后记录离开待复核队列（`rejected` 视图可见），需要显式 `reopen` 才回到可编辑状态；
  重复驳回直接返回现有版本，不产生“无限驳回”。
- 结论：`defect` 至少一个框；`no_defect` 必须没有框（写空 label 是有效结论）。
- 隔离：所有读写都带 `owner_id + project_id`，别人按 404 处理（用例覆盖）。

### 2.3 复核画布（`ReviewView.vue`）

- 左右双图（RGB / 真实配图或结果图），各自独立：滚轮以**指针为中心**缩放、拖拽平移、
  适应窗口、100%、±按钮、当前比例显示。
- 框用**原图像素**绘制在选择层里，命中/拖动/改大小都换算到图像坐标；缩放只改视图不变 bbox。
- 支持：点选、拖框移动、八向手柄改大小、空白拖拽新建、删除选中、改类别/严重程度、撤销（含 Ctrl+Z）、
  加框；`Delete` 删除、`Esc` 取消选择；输入框聚焦时不抢键。
- 提交/驳回按钮只在此页面；助手只能改草稿。

### 2.4 提交后的真实事件（无需再发“你好”）

- 提交/驳回会写一条 `kind=review_notice` 的**已完成**轻量作业（幂等键按记录+版本），
  并发 `review.submitted` 事件，带真实摘要（记录、版本、结论、框数）与 `session_id`。
- 前端会话级轮询把它显示为默认折叠的业务卡片（`lib/business.ts` 处理该事件），
  不需要用户再发消息，也不需要再调一次模型；关闭侧栏后重开仍能靠 `seq` 游标补齐。
- 证据：`test_submit_emits_session_event_without_new_message`（HTTP 提交 → `job-events` 里
  有该事件、会话消息数不变）+ 前端 `job.summary/review.submitted` 卡片单测。

## 4. 样本身份与重复检查

- 三层指纹：`sha256`（原始字节）、`pixel_sha256`（解码后 RGB 像素 + 尺寸）、`sample_key`（来源键，
  只追溯）。同名/同大小/修改时间**不参与**判定。
- `dataset_report` 只读输出：重复组、跨划分泄漏、标注冲突、缺身份样本数，并明确“不会自动删除或合并”。
- `match_records` 把记录原图与数据集样本比对：`unique` / `new` / `ambiguous`（多命中）/ `missing`；
  歧义只返回候选，必须由用户选。
- 检测前指纹复核：`run_detection` 在**建记录之前**核对权重 SHA 与 RGB 资产 SHA，
  推理前再按字节校验一次（含 X 配图）；不一致分别 `MODEL_WEIGHT_CHANGED` / `ASSET_CORRUPTED`，
  不会用“路径相同”当成同一来源。

## 9. 页面联调补修：普通账号复核页真实加载失败（2026-11-05 第三段）

协作者在真实浏览器（独立服务 5887、member `review_member`、真实记录
`det_55d5547d569a4f2e`，03 检查点 YOLOMM CPU 检测产物）实测复核页报
`Cannot read properties of undefined (reading 'draft')`，图片不加载、按钮全禁用。
本轮只修这个故障与它牵出的契约/页面问题；不回退已通过的检查点。

### 9.1 根因（一处契约不一致，不是页面健壮性问题）

`backend/routes/reviews.py` 的 `GET /projects/:pid/detections/:rid/review` 直接
`ok(state)` 返回**裸 state**，而同文件的 draft / reopen 返回 `{"state": ...}`，
前端适配器 `getReviewState` 也声明 `{state: ReviewState}`，`ReviewView.load` 读
`data.state.draft` → undefined → TypeError 被 catch → 空页面。
修法是**统一路由**：GET 也返回 `{"state": ...}`（与 draft/reopen/前端三方一致），
并在 `load()` 里加显式形状守卫——形状不对就报"复核接口返回结构不符合预期"，
绝不捕获 TypeError 后继续渲染空页面，也不用可选链掩盖。
配套回归：`test_business_wb17_04.ReviewFlowTest.test_http_review_endpoints_share_the_state_envelope`
用真实 HTTP 断言 GET/草稿/驳回/重开四条接口的信封形状。

### 9.2 新增页面适配器→HTTP 契约逐条核对（不能只靠服务层单测）

把 `scripts/contract_frontend.py` 的 Node 侧（`frontend/tests/contract_e2e.ts`，
import 真实 `business.ts`）扩成一条**真实 HTTP 全链路**：普通 member 登录 →
上传 RGB/IR → 真实 `detectOne` 产记录 → `getReviewState` → 保存**空**草稿 →
重新读取仍为空 → `submitReview` 确认无缺陷 → 再进复核页不复活旧框 →
`addFeedback` + `listFeedback` → `datasetReport` / `matchRecords` →
`saveReflowDraft`（ready）→ `reflowPreview`（0 冲突）→ `finalizeReflowDraft`
（生成 kind=revision、parent 指向原集）→ 导出 ZIP 真实字节（PK 头）→
修订版样本 RGB/IR 都在 → `listReviewQueue` 已确认队列计数。
三张图（RGB/IR/结果图）在 Node 里按真实字节校验：200 + image/* + >1KB。
Python 侧断言每个关键步骤（见脚本 29 条 PASS）。

## 10. 标注交互补修：角点拖拽失效与隐式画框（2026-11-05 第四段）

协作者真实浏览器复现：21% 显示比例下从框东南角 `[450,456]` 拖到 `[475,478]`，

### 10.1 根因（事件分支漏了目标，不是几何公式错）

`ReviewView.vue::onDown` 命中角点时只设了 `drag.mode='resize'` 和 `drag.handle`，
**没设 `drag.boxIndex`**；而 `onMove` 的 resize 分支要求 `drag.boxIndex >= 0`，
于是这条分支每次都被整段跳过 —— 手柄命中、移动判定是两段割裂的状态。
修法是把“这次按下意味着什么”抽成纯函数并让**返回值自带目标**，调用方想漏都漏不掉：

- 新增 `frontend/src/lib/interaction.ts`：
  - `beginDrag({tool, editable, boxes, selected, point, scale})` → `{mode, index, handle}`，
    `resize`/`move` 必带有效 `index`；顺序刻意为先认框再认角点（命中谁就动谁，
    按在另一个框上时绝不去缩放当前选中的框）；
  - `dragBoxes(...)`：每帧从按下时的快照重算，不做逐帧累积；
  - `endDrag(...)`：画框落地、移动/缩放按“是否真的变了”决定压不压撤销，
    没有真实移动就不压（Ctrl+Z 不空转）；
  - `toolHint(tool, editable)`：把“当前按下会发生什么”写在工具条上。
- `tests/interaction.test.ts`（11 项）用**协作者同一组屏幕坐标**重放按下→移动→松开：
  框从 `384×307.2` 变到约 `503×412`，并覆盖“resize 必带 index”“按在别的框上是 move”、
  “空白默认平移”“画框只由画框工具触发”“点一下不产 0 面积框”“不可编辑只平移”、
  “无移动不压撤销”“缩放夹在图像内”。

## 11. 历史样本身份与回流表单补修（2026-11-05 第五段）

协作者在 5887 实例上以 member 身份走完真实链路：记录 → 删空标注 → 保存空草稿 →
刷新 0 框 → 确认无缺陷 v1 → 加反馈 → 数据回流，选「回原修订/回原替换」得到
**NEW_IMAGE**。只读诊断 `WB17-04历史样本身份诊断.json` 证明资产 SHA 与原始
`train/000084` 的 SHA 完全一致（`1f063b13…52efc7`）。这不是匹配逻辑写错，
是**旧样本没有可用于比对的字段**。

### 11.1 根因：03 期导入的样本在 04 升级后身份字段全为 NULL

`dataset_samples` 的三个身份列（`sha256` / `pixel_sha256` / `origin_sample_key`）
是 04 才加的列。03 期导入的 3 条历史样本升级后为 NULL，而 04 的匹配只读这三列，
于是任何上传图都只能落进 `new`。修法不是补一条 UPDATE，也不是把回流改成追加：

- **`prepare_samples()` 成为唯一身份入口**。`preview`、`dataset_report`、
  `match_records`、`resplit` 全部走它，依据一致。
- 它用授权目录里的**真实文件**读指纹（`inspect_sample`），不是猜、不是沿用缓存。
- 只回填 `derived`（原指纹本来就空）的行；`origin_sample_key` 按导入布局还原为
  `<split>/<stem>`（如 `train/000084`），这是**溯源信息**，不参与同图判定。
- 迁移 **v11** 只加文件戳两列 `identity_size` / `identity_mtime_ns`，用来判断缓存
  是否还对得上当前文件；**不伪造任何指纹**。

身份状态与处理：

| 状态 | 判定 | 处理 |
| --- | --- | --- |
| `cached` | 有缓存指纹且文件戳一致 | 直接用缓存 |
| `derived` | 原指纹为 NULL，从真实文件算出 | 回填指纹 + 文件戳 |
| `drift` | 文件戳变了且重算内容与缓存指纹不同 | **报 `SAMPLE_CHANGED`，不覆盖缓存** |
| `missing` / `unreadable` | 文件没了 / 解不开 | 报 `SAMPLE_MISSING` / `SAMPLE_UNREADABLE` |

关键点：**缓存指纹不能反过来否认当前文件已变**。`drift` 时保留旧指纹（历史可追溯），
但明确报错要求重新核验，绝不拿未核实的数据当新图追加。

### 11.2 靠“来源键相同”不再算同图

`identity.match_record` 原本把 `transformed`（来源路径/键相同）计入强匹配，
单个候选时直接 `unique`，`reflow._plan` 就自动替换了——这与函数自己的文档矛盾。

现在按证据强度分层（`is_strong()`）：只有 `sha256` / `pixel` / `user_selected`
是强证据；`transformed` 只算**候选**，`visual_similar` 只是提示。

- 状态顺序：`ambiguous`（>1 强匹配）→ `unique`（恰 1 强匹配）→
  `candidate`（只有同来源键候选）→ `new`。
- `candidate` + 动作 `replace` → 冲突 `MATCH_NEEDS_CHOICE`，把强匹配与候选都列出来
  让人选；`append` 允许（写自己的字节与坐标）。
- 显式选目标仍保留，但不能默默把不相容坐标写给另一张图：
  `SAMPLE_CHANGED`（目标是 drift 行）、`TARGET_SIZE_MISMATCH`（样本宽高与版本
  宽高都非 0 且不等）都直接拒。
- 只把**同来源键**候选纳入 `candidate`。纯 `visual_similar` 不纳入——平整图（无纹理）
  的 16×16 均值哈希天然相同，若也算候选，任何新图都会变成“必须选”，
  回原修订就彻底走不通。这一点在代码里有注释说明。

### 11.3 表单改过就不能执行旧预览

`ReflowView` 原来只监听父数据集，改了模式/名称/反馈/动作/目标样本/划分/比例/种子
之后，上一份预览和 `draftId` 仍然可用于定稿。现在：

- `frontend/src/lib/reflow.ts` 是纯逻辑：`formSnapshot()` 把**所有影响计划的输入**
  序列化成快照，`isPlanStale()` 比对。
- `preview()` 在发请求**之前**抓快照，成功后才写入 `previewedState`；
  `apply()` 先判 `planStale` 就直接拒绝，不发请求。
- 服务端再加一道：`finalize_draft` 从库里存的 selections **重算** `preview()`，
  与保存草稿时的 `signature` 不一致就 `409 PLAN_STALE`。UI 文字不构成放行条件。
- **显示的选项必须等于真正提交的**：初始 action/split 的 `<select>` 曾有

| 情形 | 判定 | 是否解码 |
| --- | --- | --- |
| 字节 == 记录的 `sha256` | `cached`（内容必然没变） | **不解码**，直接沿用记录的 `pixel_sha256` |
| 字节 != 记录的 `sha256` | `drift` + `SAMPLE_CHANGED` | 解码一次，只为把“像素是否也变了”写进原因 |
| 只有 `pixel_sha256` 的行 | 解码后比像素：一致 `cached`，不一致 `drift` | 必须解码 |
| 两列都 NULL（03 老行） | `derived`，按真实文件补齐 | 解码 |

- `mtime`/`size` 只决定“要不要顺手刷新戳”，**不决定身份**；戳对上也要读字节。
- 常规路径（绝大多数文件没动过）只多一次读盘 + 一次 sha256，不额外解码——
  这正是“字节一致时无需重复像素解码”。
- `identity_size`/`identity_mtime_ns` 两列保留，但定位改为**诊断/审计提示**：
  能看出“文件在导入后被碰过”，不能用来跳过核验。
- 顺手补空列：老的“只有字节指纹”行在字节一致时补一次像素指纹，之后可按同图比对；
  “只有像素指纹”的行补字节指纹。更新语句用 `CASE WHEN ... IS NULL OR = ''`，
  **只填空列、绝不覆盖已有指纹**。

### 12.2 连带修正：已改文件的样本不能当替换目标

修好缓存后暴露出一个一致性问题：漂移样本若继续用**记录的**指纹参与匹配，
一条同字节的记录仍会 `unique` 命中它——但磁盘上已经不是那张图，坐标不该写进去。

- `match_record`：命中漂移样本时标记 `stale_identity`，`is_strong()` 不认它，
  于是状态落到 `candidate` 而**不是** `unique`，`_plan` 报 `MATCH_NEEDS_CHOICE`，
  不会自动替换、也不会误报 `NEW_IMAGE`（探针的 `changed_file_status` 现在是 `candidate`）。
- 漂移样本只进 `hints`（提示“大概就是它，但文件变了”），**不进可选目标列表**；
  显式选它仍被 `SAMPLE_CHANGED` 拒。
- 自动命中分支也加了同一道闸：即使状态走到 `len(matches) == 1`，目标是漂移样本就停，
  保证预览里的“替换 N 条”不会把不可用的样本算进去。
- 没有新增第二套判断：仍然只有 `inspect_sample` 一个状态来源，`_plan` 只读状态。
