## 1. 反馈池有效版本口径（本批唯一的业务修正）

**问题**（root `反馈池有效版本独立核验` 5 项 3 失败）：`records.list_feedback` 只按存储
status 筛，不看当前生效人工版本/记录活动状态，导致 v1+v2 双行 pending、驳回后旧
confirmed 仍 pending、软删记录反馈仍 pending。

**修法（最小查询口径，不引入 void 转换，不动历史行）**：

- `pending` 只取：记录未软删（`detections.deleted_at IS NULL`）+ 反馈绑定的版本就是该
  记录**最近一次已提交**版本（与 `review.effective_review` 同序）且状态为 `confirmed`；
- 过滤全部在 SQL 的 `LIMIT` 之前（先截页再过滤会漏项）；
- `status=all/reflowed/void` 保持全量历史（旧 `all` 误当真实 status 值的缺陷一并修掉）；
- 回流校验 `STALE_FEEDBACK` 同步改为"选中版本本身有没有 pending 反馈"：旧版本 pending
  行是历史，不再把新版本的回流永远卡成冲突（旧用例 `test_stale_feedback_blocks_reflow_after_new_version`
  语义保持）。

**回归**：`backend/tests/test_business_wb17_e_feedback_queue.py` 7 例——双确认只剩最新、
驳回出队留史、软删出队/恢复可取回、**filter-before-limit**（过期行更新但有效行更旧，
limit=1 不漏）、页面 HTTP 与 `hx_list_feedback` 工具同库同结果、记录页 feedback_status 与
队列一致、新版本反馈可回流而旧行留史。受影响子集（04/b/c/e）55+ passed。
