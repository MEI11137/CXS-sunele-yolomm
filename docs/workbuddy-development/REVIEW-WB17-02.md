## 实际发现并交 WorkBuddy 修复的关键问题

1. 不能用 HTTP 200 的普通文字回复认定支持视觉或工具调用；增加真实挑战及证据范围校验。
2. MCP 子进程在项目目录启动时模块不可导入；改为工程内确定的入口。
3. 工具令牌不能在第一轮结束后让后续轮次永久失效；同时处理过期、明确撤销和缓存进程的区别。
4. Native ID 的复用需核对存储代次和真实存在性；超时不能冒充 404 重建并重发。
5. stop 请求必须阻止新的动作；abort 未确认空闲要隔离旧进程与令牌，既有业务结果如实报告。
6. 相同调用并发需原子认领；确认执行时复查当前权限与操作状态。
7. 读取发起前历史基线失败不能当成空历史；有界只读重试，仍失败则在 prompt 之前终止。
8. 前端历史按会话隔离，最终正文以真实落库消息为准；人工确认区固定在输入框上方。
