## 2. MCP 错误映射与 Windows stdio 中文乱码

### 根因与修复（`backend/mcp_client.py`）

- **NoEventLoopError**：`_map_sdk_error` 在同步线程里调
  `anyio.get_cancelled_exc_class()`，sniffio 无事件循环直接抛错，掩盖真实连接失败
  （root 日志：`test_http_error_is_reported_honestly` data=None）。修复：
  `_cancelled_exc_classes()` 三路兜底（asyncio 取消类 / anyio 能问就问 / trio 装了
  也认），**任何上下文都不抛错**。
- **原始错误丢失**：worker 在 `async with` **内部**就把 CancelledError 吞进收件箱，
  任务组没机会把底层 ConnectError 打包上抛。修复：worker 重构为外层统一
  try/except，取消类异常穿出两层 `__aexit__` 让任务组解包，按 `current_rid` 回传；
  `_map_sdk_error` 先 `_flatten_group` 展平 ExceptionGroup，挑出非取消成员——
  "连不上"如实映射 `MCP_UNREACHABLE`，不再笼统说"连接被中断"。远端 `McpError`
  的原始 code 保留在消息里（`code=-32000`）。
- **stdio 中文乱码**：Windows 上 Python 子进程往管道写 stdout 默认 GBK，父进程按
  UTF-8 解码成 `ע:热斑`。修复：`StdioSession.open()` 给子进程 env
  `setdefault("PYTHONIOENCODING", "utf-8")`（JSON-RPC over stdio 协议要求 UTF-8；
  用户显式配置的 env 优先；仍是最小 env，不读整份服务器环境、不改系统编码）。

### 验证

`test_business_wb17_05_mcp.py` **25/25 全过**（此前 2 失败 1 错误均在其中：
两条中文断言 + HTTP 错误如实上报——断言未改动）。新增
`McpErrorMappingTest` 3 例：无事件循环映射不抛（CONNECTION_CLOSED）；取消+ConnectError
的 ExceptionGroup 展平后映射 UNREACHABLE；SDK 错误码保留。

## 3. 受控命令三个拒绝反例（root：`verify_phase05_shell_edges.py`）

### 根因与修复（`backend/agent/shell.py`）

| 反例 | 根因 | 修复 |
| --- | --- | --- |
| 超 260 字符绝对路径被放行 | `_looks_like_path` 用 `len(text) > 260 → False` 直接跳过检查 | 删除长度短路：先判"像不像路径"，像就查，**与长度无关**；报错信息截 80 字符防刷屏 |
| `Registry::HKEY_CURRENT_USER` provider 路径放行 | 无任何 provider 前缀检测 | `_PROVIDER_PATH = ^[A-Za-z][A-Za-z0-9]*::`：识别与拒绝均覆盖（`_looks_like_path` 与 `_path_problem`），明确报"非文件系统 provider 路径" |
| `ForEach-Object -MemberName Delete` 间接成员调用放行 | AST 只收集命令名/字符串/变量，参数不在收集范围（`member_invokes` 只抓 `.Method()` 语法） | 分析器新增**参数收集**（`CommandParameterAst`）；Python 侧对 `foreach-object` 的 `-MemberName/-Method`（含缩写：任何能前缀解析到这两个名字的参数）一律拒绝——无法证明影响就不放行 |

文档与报错口径同步：模块 docstring 明确"这套检查不等于 PowerShell 成了完整沙箱"；
cwd 仍只是 cwd 不是沙箱。参数缩写/别名保守处理（别名命令名本就不在允许清单，照旧拒绝）。

### 验证（只分析、不执行被测危险命令）

## 4. 识别记录：筛选总数 / 刷新上下文 / 深链定位（root UI-04A）

  `COUNT(clauses[:4])`。修复：筛选子句与分页游标子句**分开维护**，计数用全部筛选
  条件（状态/模型/会话/命中/回收站/文件名搜索）且不随游标缩减（`backend/services/detection.py`）。

## 6. CUDA 指定索引校验（root：`_default_device_probe('cuda:15')` 返回 ok=True）

根因：默认探针只看 `torch.cuda.is_available()`，从不比对序号与 `device_count`。
修复（`backend/services/training.py`）：`_default_device_probe` 对 `cuda:N` 解析
序号，`ok = available and N < device_count`，detail 写明
`cuda_available=…, device_count=…, requested=cuda:N`；`_check_device` 文案同步
（"指定的序号不存在或本机探测不支持时，不会假装能跑"），计划阶段即拒绝。

验证：`CudaIndexValidationTest` 3 例（mock torch.cuda：is_available=True /
device_count=1）：cuda:15 探针 ok=False 且 detail 含真实卡数；
cpu/cuda/cuda:0 照常通过；`_check_device('cuda:15')` 抛 409
`TRAINING_DEVICE_UNAVAILABLE`，cpu/cuda:0 不抛。**未启动任何 GPU 任务。**
