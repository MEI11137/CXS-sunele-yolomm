## 1. 启动身份：判定只留一份

三个分支原本各写一套“是不是我的实例”，其中 `status` / `start` 只看 instance+PID，
没比数据目录，所以把 A 的 `server.json` 拷到 B 之后：

- `cmd_stop` 会拒绝（有 `live.data_dir` 比对），但 `cmd_status` 仍说“运行中/退出 0”；
- `cmd_start` 在相同端口直接说“已在运行/退出 0”，等于把 A 当成 B 的实例。

现在统一走 `deploy/serve.py::identity_conflict(state, live, data_dir)`：**本次解析出的
目录、`server.json` 里的 `data_dir`、服务自报的 `data_dir` 三处必须同时相等**，再加上
instance 与 PID；不一致返回 `(退出码, 原因)`，`start` / `status` / `stop` 共用这一份规则，
谁也不再自己拼。

| 反例 | 修法 |
| --- | --- |
| 记录 PID 活着（就是核验器自身 PID）、probe 失败，`start` 仍去绑新端口 | 先查 `_pid_alive`：活着就返回 **6**，**在 `port_free` 之前**退出——不建第二个 app，也就不会把原轮次标成中断 |
| 拷贝 state 到 B，`status` 仍报“运行中/0” | `status` 也过 `identity_conflict`；目录对不上返回 **4**，并说明这条记录属于哪个目录 |
| 拷贝 state 到 B，`start` 仍报“已在运行/0” | 同上：先判身份，异目录记录**直接拒绝（4）**，不误当 B 的实例，也不下去绑端口 |
| `active_work` 吞掉不可读/损坏的 SQLite 异常 → `{}` | 新增 `WorkStateUnknown`：库打不开、文件不是数据库、缺表、任一统计查询失败都抛出；`stop` 返回 **10** 并拒绝普通停止；`--force` 的既有语义保留（照停）；检查仍只用 `mode=ro`，不迁移、不建表、不改一行 |

**清理旧记录的时机**：`start` 只有在 `probe` 失败**且** `_pid_alive` 为假时才
`remove_state()` 后继续；PID 还活着就保留记录，把判断交给人。

退出码表补全，并同时写进 `deploy/serve.py` 的模块文档串与 `停止海巡智检.cmd` 尾部提示：
`0` 成功 · `1` 环境检查失败 · `3` 未响应 · `4` 异目录记录/同目录已有实例 · `5` 端口被占 ·
`6` PID 活但不响应 · `7` 端口上是别的服务 · `8` 停止未确认 · `9` 有进行中任务 ·
`10` 任务状态未知。

## 2. 服务管理接口：把“防反代”说到做到

原文档串写“只接受本机回环地址，即使外面套了反向代理也不放行”，但只查 `remote_addr`
做不到——同机反代本来就是 127.0.0.1。现在：

- 保留随机令牌（128 位，只写 `run/server.json`，`hmac.compare_digest` 比对，永不回显）；
- **新增转发头拒绝**：`Forwarded`、`X-Forwarded-For/Host/Proto/Port`、`X-Real-IP`、
  `X-Client-IP`、`True-Client-IP`、`CF-Connecting-IP`、`CF-Ray` 任一出现即
  403 `SERVICE_PROXY_REJECTED`（nginx 与 Cloudflare 隧道默认都会加这些头）；
- 文档串改为如实说明范围：**真正的边界是随机令牌**，回环地址与转发头检查是加固；
  同机反代若主动剥掉转发头，与本地调用不可区分，所以“不要把管理端口暴露到公网”，
  不再声称“套了反代一定进不来”；
- 没有为管理调用放开任何业务接口的 CSRF：`auth._guard_state_changing` 只对**带会话
  Cookie** 的请求生效，启动器不带 Cookie，本来就不触发；令牌不进 health/meta/页面。

反例用例（`backend/tests/test_deploy_service.py` 新增 3 条，共 7 条）：转发头 403、
非回环 403、令牌不出现在 health / meta / 自身状态响应里。

## 4. 双击入口：批处理改回 GBK/CP936

改文档时发现 `.cmd` 里的**条件分支**在 UTF-8 无 BOM + `chcp 65001` 下会被 cmd.exe 按
GBK 解析，出现命令名被截断、`:label` 跳错位的现象（实测
`if not "%CODE%"=="0" echo …` 报 `'外都没有结束任何进程' 不是内部或外部命令`；
加 BOM 更糟，连 `@echo off` 都被当成命令）。三个入口统一改为 **GBK + CRLF + `chcp 936`**
（Windows 批处理的原生编码），实测顺序回显、`goto`、`if (...)` 块、退出码传递全部正确；
Python 自身输出走控制台 API，中文显示不受影响。

同时给 `停止海巡智检.cmd` 补了解释器检查（缺 Python 时原来只丢一个 9009，没有任何提示），
现在与启动/准备脚本一致：`HX17_PYTHON` → `.venv` → PATH `python`，找不到就给出中文指引并
`exit /b 1`。

复测：`.\启动海巡智检.cmd`（私有数据目录 + 8123 端口）→ `/api/health` 200、`run/server.json`
写对（PID/端口/instance/data_dir）；`.\停止海巡智检.cmd` → 退出码 0、记录清除、端口释放；
`HX17_PYTHON` 指向不存在的路径 → 退出码 1 且提示正确。

## 6. 文档：命令块按标注的 shell 真能复制执行

- `docs/WB17-06-换机部署.md` 命令块重写：PowerShell 5.1 不支持 `&&`、也不认 `set VAR=值`，
  一律分行 + `$env:VAR='值'`；从 PS 调当前目录的批处理必须 `.\启动海巡智检.cmd` /
  `.\停止海巡智检.cmd`；`cmd` 段落单独给（无 `.\` 前缀、用 `set`）；`--stop [--force]`
  方括号不是可复制实参，拆成两条，强停单独成段并说明“会中断轮次、可能终止训练子进程”，
  不放进默认流程；`curl` 一律写 `curl.exe`（5.1 里 `curl` 是 `Invoke-WebRequest` 的别名）；
  `setx` 标注**只影响之后新开的进程**，当前窗口要用 `$env:`。
- 自检命令改用标准库：`python -m unittest discover -s backend/tests -t .`——`requirements.txt`
  **不含 pytest**，不能让人照抄 `-m pytest` 在一个全新 venv 里失败；真实 CPU 微训练给的是
  精确点号方法名 + `$env:HX17_RUN_REAL_TRAINING_TEST='1'`，默认仍是显式 opt-in，
  跳过不代表通过。
- 备份范围改成事实：`HX17_DATA_DIR` 里是 `haixun.db`、`secrets/`、`run/`、引擎隔离目录；
  业务数据集、原图、权重、回流产物、训练输出在**项目绑定目录**
  （`projects.root_path`，其下 `uploads/ artifacts/ datasets/ training/ .cache/`），
  冷备必须两块都备；“同机冷备还原”与“换机新部署”分开写：新机器自己生成 DB/密钥/账号，
  不拷贝开发 QA 库覆盖，也不为迁就文案合并或搬动已有目录。
- `README.md` 同步：初始化/运行/测试命令按 shell 整理；数据目录与业务文件的区别；
  管理接口防护范围（随机令牌是边界、转发头 403、不要把管理端口暴露公网）。
