## 2. 数据模型（迁移版本 1 → 2）

`users`、`auth_sessions`、`allowed_roots`、`root_grants`、`projects`、`sessions`、`messages`、`connections`、`audit_log`。
全部通过 `PRAGMA user_version` 管理，迁移脚本只追加不修改。关键约束：

- `users.username` 唯一（`COLLATE NOCASE`），`token_version` 用于一次性作废旧令牌；
- `auth_sessions.expires_at` 用 epoch 秒，吊销以 `revoked_at` 标记，服务端判定优先于令牌自身 exp；
- `allowed_roots` 是管理员登记的目录白名单；`root_grants(root_id, user_id)` 决定“哪个账号能用哪个根”，
  **默认不共享**。v2 迁移只建关系表，不把历史全局授权自动发给任何账号（有单独测试）；
- `projects`/`sessions` 的 `status ∈ (active, deleted)`，`deleted_at` 可空；
- `connections.user_id` 是主键，一个账号只有一份连接；
- `audit_log` 记录登录、账号状态、目录授权/授予/收回/绑定、连接保存与检查。

## 4. 安全决策与权衡

1. **令牌与吊销**：令牌用 Flask 已依赖的 itsdangerous `URLSafeSerializer` 签名，只用于识别会话；
   有效性以 `auth_sessions` + `users.status` + `token_version` 为准。登出/停用/改密都走同一条校验，
   不依赖前端删 Cookie。畸形 Unicode、无效 base64、非 dict 载荷、错误 exp 类型统一返回未登录。
2. **CSRF**：写操作要求 `X-CSRF-Token` 与 `hx17_csrf` Cookie 双提交一致，并校验 `Origin`；
   只接受 `application/json`（跨站表单无法伪造该 Content-Type）。未登录请求不要求 CSRF（无环境凭据可利用）。
3. **口令**：`scrypt(n=2^14,r=8,p=1)`，失败回退 PBKDF2-240k，存储带算法前缀；账号不存在也跑一次哈希。
   登录失败按 `IP|用户名` 8 次/5 分钟节流，节流实例挂在应用上，避免多实例/测试互相污染。
4. **目录**：`realpath` 归一化后 `commonpath` 判断包含关系；盘符相对（`C:foo`）、`\\?\`、UNC 一律 400；
   `..` 与符号链接/NTFS 联接由归一化消解，越界即 403。UNC 采取“统一拒绝 + 要求映射盘符”的策略，
   因为远程共享是否在授权范围内无法只凭本地路径证明。授权根本身不允许是磁盘根。
   **授权按账号**：列表、浏览、绑定只用本人 `root_grants`；已绑定项目每次访问都重新校验，撤销即 403
   `GRANT_REVOKED`；管理员可显式把同一根授予多人，但新根默认零授予。
5. **绑定替换**：已有绑定且新目录不同 → 409 `ROOT_ALREADY_BOUND`，必须 `replace=true` 且前端二次确认；
   审计记录 `旧值 -> 新值`。移除授权根时若仍有项目绑定其内 → 409，避免项目留在授权范围之外。
6. **越权返回码**：他人项目/会话统一 404（不泄露存在性），与“确实不存在”不可区分。
7. **连接凭据**：AES-256-GCM，`aad` 绑定 `user_id`；主密钥在 `var/secrets/connection.key`，与 DB 分文件。
   主密钥**只在文件不存在时创建**（完整内容写临时文件 + 原子硬链接）；已有文件过短/不可读一律
   `KeyFileError` 停止启动，绝不覆盖。数据库、WAL 文件都不含明文 Key（有测试逐文件扫描断言）。
   能力结果与“保存时的 base_url + model + Key 指纹”绑定，任一变化即清空并标记 stale；
   探测期间配置被改动时，结果按条件 UPDATE 丢弃（`applied=false`），不会写成新配置的能力。
8. **公开面收敛**：`/api/health`、`/api/meta` 不再返回 `data_dir`、端口；隔离性测试改为断言
   `app.config["HX17"].db_path` 与真实建库位置。

### 10.3 本轮新发现的真实缺陷（由并发用例捕获）

`os.open` 在 Windows 默认是**文本模式**，密钥中若出现 `0x0A` 会被写成 `0x0D 0x0A`，
32 字节密钥落盘后变 33 字节；下次启动长度校验失败。该问题概率约 12%/次，表现为偶发失败。
已加 `os.O_BINARY`（POSIX 无此标志，取值 0），并新增 `test_key_file_is_written_binary_safe`
用 `bytes(range(32))` 固定断言落盘字节完全一致。

> 影响面：旧构建在开发目录里可能留下 33 字节的 `var/secrets/*.key`（本工程未发布、无生产数据）。
> 现在它会**明确报错**而不是被覆盖；处理方式是删除该数据目录重新初始化账号，或从备份恢复。
