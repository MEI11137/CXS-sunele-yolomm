## 文件规则与实现

项目输出归属由服务端核实的项目/资源决定，网页与内部 OpenCode 工具共用，不能只在最后复制一次 ZIP。

| 文件 | 当前保存规则 |
| --- | --- |
| 项目附件、数据集 ZIP、导入权重、检测原图/配图/结果、草稿图片及标签 | `<项目目录>/artifacts/<原业务分类>/` |
| 回流生成的完整数据集 | `<项目目录>/datasets/<数据集ID>/`，沿用 INT-25 ZIP、解压目录和清单 |
| 转换/合并候选目录及清单 | `<项目目录>/datasets/candidates/` |
| 训练权重、图表、CSV、指标 | `<项目目录>/training/<模型ID>/`，清理临时解压不删除训练产物 |
| 项目处理缓存、模型副本、临时上传、解压目录 | `<项目目录>/.cache/`，按既有生命周期清理 |
| 数据库、账号连接密钥、网站/引擎私有状态、头像 | 仍由网站独立保管，不复制进模型可操作的项目文件夹 |

- `services/project_storage.py` 使用 ContextVar 隔离请求/线程范围；不修改进程 cwd 或全局 TEMP。每次输出重新核对绑定目录，拒绝路径越界和重定向。
- `FileClient` 的项目对象使用 `workspace.<项目ID>.<分类>` 标识真实目录。读取仍通过原文件鉴权接口，明确拒绝向不同项目或不同数据库写入。
- 实际网站启用 `PROJECT_FILES_IN_WORKSPACE=True`。原业务页面写操作须提供实际项目，没有绑定目录就先提示绑定，不能悄悄落回后端。独立业务组件保留无网站配置时的旧契约，用于已有隔离测试与库使用。
- 业务适配层在解析真实资源后选择项目，在执行前再次进入真实目标项目；工作目录与候选目录按当前作用域计算，不变更共享单例上的当前项目。
- 手动上传、图片/视频/实时检测、模型导入、数据集草稿及定稿沿用既有服务，临时目录使用项目感知的 PathLike；上传 ZIP 补齐显式 dir，避免默认进入系统临时目录。
- 内部巡检批任务和附件登记显式继承项目范围，文件发现忽略 `.cache`，避免把处理中的副本当新输入。
- 训练子进程显式接收项目 ID，并对照真实资源归属；产物输出至训练目录，保留权重/日志/指标，临时解压独立清理。项目目录不可用等失败也释放训练锁，不留下假运行。
- 视频后台进程和草稿重试按实际项目继承文件路径。
- 内部 Agent 提示规则补充：脚本、命令及生成文件显式使用项目内输出路径，不使用系统 TEMP 或后台私有目录。

这统一的是网站已接入业务服务的文件路径。OpenCode 的任意 Shell 仍运行于本机账号，原有“未知命令确认、删除确认、外部目录拒绝”保留；工作目录不是操作系统沙箱，不把提示规则描述成能隔离任意已批准程序的 OS 权限。

## 历史文件归集与链接兼容

- 新增 `project_file_migration.py`，只处理已由网站登记归属的业务对象及附件，不让模型提交表名或认领任意路径。
- 将历史文件复制到该项目 `artifacts`，逐个验证 SHA256；保留原文件作回退，不删除或移动用户数据。
- `workspace_file_alias` 使原 bucket/key 继续指向工作区里的文件。旧 URL、人工复核图片和业务行引用不必批量重写，仍走同一套鉴权。
- 重复执行复用已有一致内容；工作区副本被用户修改、文件已有不同内容或旧对象被多个项目共同引用时停止，不能覆盖或暗中改变其他项目归属。
