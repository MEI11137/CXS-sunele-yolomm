## 1. 新增 `src/services/http.ts`：统一请求层

原先没有请求层，谁都能自己 `fetch` 一把，于是「HTTP 200 但业务 code=401」这类响应会被当成成功。现在只留一个出口：

- `request<T>()` 统一处理：Token 注入、`credentials: 'include'`（文件会话 cookie）、`{code,msg,data}` 拆包。
- **双重成功判定**：先看 HTTP 状态，再看业务 `code`。`code` 不是 200/0 一律抛错；`code=401` 额外触发登录失效。
- 失败统一抛 `ApiError`，带 `httpStatus` / `code`（稳定错误码字符串）/ `execution_state` / `details`。
  `execution_state` 缺省为 `unknown`，**不允许**把"未知是否已执行"显示成"未执行"。
- `onUnauthorized()` 订阅机制：401 时清 Token 并通知订阅方，避免 `http.ts` 反向依赖 auth store 形成循环。
- `http.blobUrl()`：受保护图片不能给 `<img>` 塞 Bearer 头，改为带 Token 取 blob 再 `URL.createObjectURL`。

## 2. 新增 `src/services/mappers.ts`：字段差异只在一处解决

| 差异点 | 后端实际 | 处理 |
| --- | --- | --- |
| 时间 | ISO 字符串 / 秒级数字 / 毫秒数字混用 | `toMillis()` 统一成毫秒，`Invalid Date` 不再出现 |
| 任务状态 | `planning/awaiting_input/awaiting_plan/awaiting_action/awaiting_human/awaiting_business/running/completed/partial_failed/failed/stopped/interrupted/unknown` | `mapTaskStatus()` 全量保留，删掉 `waiting_confirm/queued/cancelled` 三态，不再把"等待"当"排队" |
| 步骤字段 | `{id, title, status}` | `mapTask()` 转成 `{id, name, status, title}`，`step_id` 与真实状态都不丢 |
| `waiting_for` | 对象 `{kind, refs, conditions}` | `mapWaitingFor()` 结构化保留，不再退化成字符串丢业务引用 |
| 动作版本 | `revision` 是整数 | `Confirmation.revision: number`，确认时按整数回传 `expected_revision` |
| 动作摘要 / 预览 | `parameters_summary` 是字符串，`preview` 是对象 | 按原类型放进 DTO，不再 "JSON 字符串塞界面" 或反过来 |
| 执行状态 | `not_executed / partial / executed / unknown / cancelled` | `ExecutionState` 与之对齐，废弃 `not_started/running/completed` |
| 目标项目 | `target_projects` | 映射为 `actual_target_projects`，空数组不猜默认项目 |
| 登录返回 | `{userInfo:{...}, token}`，token 在外层 | `mapAuthUser()` 取嵌套 `userInfo`，缺 token 或 id 直接判失败 |
| 项目要求 | `requirements` 是对象，可写成 `notes` | `mapWorkspace()` 把 `notes` 提到界面，原对象留在 `requirements_raw`；更新时 `mergeRequirements()` 只改 `notes` |

## 3. 新增 `src/services/real-adapter.ts` + `adapter-base.ts`

- `ApiAdapter` 扩到 45 项能力（账号 / 工作区 / 个人连接 / 资源 / 文件 / 会话 / 任务 / 动作 / 工具手册授权 / 业务读写 / 旧页面读接口）。
- `BaseAdapter` 让**每一个**未实现的能力默认抛 `NotSupportedError`，页面调用到就是明确失败，
  绝不会拿到"看起来成功的空数组"。这是本轮最重要的约束。
- `RealAdapter` 覆盖到的真实端点：

| 能力 | 端点 |
| --- | --- |
| 登录/注册/当前用户/退出 | `/api/user/login`、`/api/user/register`、`/api/user/current`、`/api/user/logout` |
| 首屏聚合 / 项目 | `/api/agent/workspace`、`/api/agent/projects`（GET/POST/PATCH） |
| 项目资源 | `/api/agent/projects/:id/resources` |
| 个人连接 | `/api/agent/connection`（GET/PUT/DELETE）、`/connection/check` |
| 会话与消息 | `/api/agent/sessions`、`/sessions/:id/messages`、`/sessions/:id` |
| 事件 | `/api/agent/sessions/:id/events?after=` |
| 任务 | `/api/agent/tasks/:id`、`/plan/confirm`、`/stop`、`/reconcile`、`/note` |
| 动作 | `/api/agent/actions/:id/confirm`（带 `expected_revision`）、`/reject` |
| 工具/手册/授权 | `/api/agent/tools`、`/manuals`、`/grants` |
| 文件 | `POST /api/file/project/:pid/upload`、`GET /api/file/metadata/:id`、`GET /api/file/:bucket/:key`（blob） |
| 记录 / 核查 / 标注 / 反馈 | `/api/detection/records`、`/:id`、`/ai-review`、`/human-review`、`/feedback` |
| 类别 / 数据集 / 模型 / 对比 | `/api/model/classes`、`/api/dataset/list`、`/api/model/list`、`/api/model/:p/compare/:c` |

- 事件按 **session** 取（不是按 task），返回包里的 `task_id` 再用于分组。
- `sendMessage` 返回 `ChatTurn`（`reply/task/action/plan/events_after`），因为后端这一轮是复合结果，
  不是单条 `ChatMessage`；同时**不伪造逐字流式**，`onDelta` 在真实模式下不触发。
- `createTask` 在真实模式下**显式抛错**：任务只能由对话产生，页面直连创建等于绕过计划与确认。

## 5. 真实登录与账号隔离

- `stores/auth.ts` 重写：
  - `login()` 必须由后端校验，失败**不产生**登录态，错误文案回到浮层。
  - Token 存 `haixun.token`，用户资料存 `haixun.auth`，**不把 Token 写进用户对象**。
  - `bootstrap()` 启动时用 Token 拉 `/api/user/current` 复核身份，失败即清空。
  - `clearAccountState()`：登出/切号时清 Token、用户资料、选中工作区、会话与消息、复核队列与标注缓存，并重建适配器。
  - 订阅 `onUnauthorized()`，任何 401 立即失效登录态。
  - 删除所有"登录后可云端查看"的说法：本机部署就是本机部署。
- `AuthModal.vue`：提交改为 `await auth.login()`，注册后**再走一次真实登录**（避免"注册即登录"假象），
  按钮带提交中态；文案改为「不登录只能只读浏览」；底部提示按模式区分「演示模式」与「本机部署」。
- `AccountFooter.vue`：字段改为 `realName || username`，角色文案去掉"云端模式"。
- `App.vue`：先 `auth.bootstrap()` 再加载数据；未登录时 401 只记日志并保留空状态，不伪造数据。
