## 1. 卡点与修改

1. 旧流程要求每个本地附件分别登记、每张图片单独检测和确认，内部 Agent 因缺乏批任务入口而反复停下。本次新增 `agent/inspection_loop.py`，由 OpenCode 原有 MCP 工具循环选择工具，后台仅串接已有业务服务，不另造规划 Agent。
2. 新增项目目录只读发现、整轮巡检、批次真实状态、人工确认样本分组回流四项工具。发现返回真实类别、模态及数量摘要；参数齐全后，提示模型直接调用整轮工具，不再先用 Shell 逐个目录数图。
3. 整轮确认卡持久化项目、路径、哈希、类别索引、RGB/X 配对、确切样本、置信度、AI 调用次数及发布影响。批次内复用原服务的权限、预检、幂等请求和资源归属登记；未批准不执行。
4. 同源数据集和权重可以复用已登记资源；新一轮也可提供项目内真实 `model_id` 使用迭代模型，避免必须从受保护业务存储中手抄权重路径。
5. 后台记录每个阶段和每张图片的结果。独立失败不阻断其他图片；依赖失败停止；付费核查、未知写入及训练不会自动换键重做。任务停止、页面刷新、后端重启均以持久化和真实业务状态处理。
6. 疑点/失败记录进入按批次过滤的人工复核页，并发送项目内导航事件及持久化人工入口；AI 一致不等于人工确认，也不自动回流一致样本。
7. 复核页补充 AI 摘要、关注区域/疑似漏检坐标，以及原始 RGB/配套模态图对照；标注仍使用 RGB 归一化坐标。修复类别 ID 为 0 时被 `|| index` 错当缺省值的问题。
8. 人工提交后查询真实标注版本，全部处理完再询问回流去向。支持分组生成原数据集修订版或独立新数据集，按图像内容匹配原样本并替换标签，不覆盖源文件、不复制图片伪造验证集；驳回项不能回流。可在同一回流计划中明确增量训练参数、是否发布及实际归档范围。
9. 修复 Windows 中文路径中 OpenCV 图片读取/写入失败；通过 Python 读写字节配合 imdecode/imencode，原推理入口继续使用。
10. 检测结果显示名统一按关联数据集的真实类别索引表生成；越界类别拒绝处理，防止英文权重显示名与中文复核/反馈类别不一致。

## 2. DeepSeek 视觉检查修复

- 实际配置：官方地址 `https://api.deepseek.com`，API ID `deepseek-flash`。官方文档确认此 ID 对应原生多模态 V4.1 Flash，不能因名称简写就认定选错模型。
- 旧探测 PNG 解码失败，接口拒绝无效图片，旧程序将错误泛化成“不支持图片”。排查中又发现仅调用 Pillow load 不足以检查 PNG CRC；因此最终改为标准库动态生成带正确 CRC 的 PNG，并在测试中同时 verify 和完整解码。
- 错误分类保留无效图片、能力不支持、认证、限流、网络等区别。当前连接已完成真实图片探测，`vision=ok`。
- 选择器在官方接口下显示 `DeepSeek V4.1 Flash`，同时显示真实 API ID，支持按两种名称搜索；自定义兼容接口不擅自套用官方品牌映射。
- 未更换用户 Key、模型 ID 或服务地址。

## 3. 开发接口

- 新增本机限定 REST 开发连接及 `agent/developer_mcp.py` stdio MCP，预留给 Codex 和 DeepSeek Harness。
- 管理员主动创建后，仅授权其一个项目下的独立开发会话；令牌 4 小时过期、可撤销、只返回一次，数据库只存哈希。
- 只提供读状态及发送带来源标记的诊断消息。同一请求键防重复；已有任务/批准/人工等待时不插队。没有批准、提权、人工提交或删除工具。
- 未自动创建真实开发令牌（实际表中连接数为 0），未改用户 Codex/Harness 全局配置；没有用外部 Agent 替代内部业务闭环。
