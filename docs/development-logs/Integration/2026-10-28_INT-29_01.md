## 1. 业务能力补齐

- 新增 `agent/resource_tools.py`：`workspace_query_resources` 按真实名称、状态查询数据集/模型/草稿/识别记录及回收站，返回实际 ID 和资源 revision。
- `workspace_manage_resource` 为数据集、模型、草稿生成删除/恢复确认卡；服务端要求当前任务实际执行中的 action、参数、prepared_id、request_key 全部一致，模型自报 confirmed 不生效。
- `workspace_draft_samples` 读取实际样本 ID/文件名/划分/配对状态，不把后台文件存储路径发送给模型。
- 按用户最新要求将 `draft.assign_splits` 从旧“人工页面专用”改为 Agent 可调用写工具；沿用原划分服务、参数校验、资源权限和确认卡，未放开自动人工标注。
- `workspace_open_page` 可带数据集页签、草稿 ID、识别记录筛选状态。前端响应对应路由，不要求用户另选工作区。
- 原检测、核查、导入、反馈、草稿定稿、训练/对比/发布等已有工具继续使用；任务手册和旧聊天不是拒绝最新可用工具的依据。

## 2. 页面与 Agent 共用可恢复删除

- 公共服务 `services/resource_lifecycle.py`：使用索引的 deleted_at 隐藏资源，不删 datasets/models/dataset_drafts 的业务行及文件。
- Schema 9：给 agent_resource 加 deleted_at，增加 agent_resource_change 操作审计与幂等结果表；加法迁移，没有覆盖旧数据。
- 删除前与执行时检查项目/用户/系统默认只读边界、当前 revision、其他活动任务、在用数据集、训练中/已发布模型、正在生成的草稿；恢复模型时先检查来源数据集已恢复。
- 已发布模型必须先撤销发布；恢复不会重新发布、启动训练或级联恢复其他资源。
- 页面列表、正常资源解析、模型发布范围和业务权限桥均排除已删除资源；历史业务行/文件保留供审计。原 DELETE 数据集/模型路由也改用公共服务，移除旧物理删除逻辑。
- 新接口：GET `/api/agent/resources/lifecycle`；GET/POST `/api/agent/resources/lifecycle/<kind>/<id>`，当前账号与项目鉴权，预览后携带 expected_revision 执行。
- 数据集及候选草稿列表增加删除，模型增加删除和撤销发布；两页增加回收站恢复。手动操作仍需显示对象、项目、版本、影响再确认。
- Agent 写入后向当前项目页面通知资源变化；导入、检测、反馈、定稿、划分等现有业务写入结果也触发相关页面刷新，避免助手完成后列表仍旧。

## 3. 滚轮缩放

- AnnotationCanvas 在图片区域处理滚轮：上滚＋10个百分点，下滚－10个百分点，范围50%–300%；顶部百分比和原缩放按钮共用 zoom 状态。
- 缩放以鼠标指向的图像位置为锚点，靠近边缘时遵守视口滚动边界；拖框/画框/平移中不同时改变缩放。
- 原图和结果图共用可缩放画布。结果图只读，强制平移，禁用结果视图中的标注编辑按钮；原图保留手动标注与原有平移方式。
- 只改变视图，不改变标注坐标、人工状态或记录版本。
