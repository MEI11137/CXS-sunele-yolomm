## 用户目标

用本机开源 OpenCode 替换自建模型/工具循环，改善一般问答和文件任务能力；保留现有网站和业务闭环。同时说明默认免费模型来源、软件许可和赛事平台要求。

## 实际实现

1. `agent/opencode_engine.py`：调用已安装 OpenCode 1.19.4；按用户/站点会话隔离进程与运行目录，随机本机服务凭据，限定本人模型连接。默认最多 4 个实例，凭据或工具清单变化时重建连接并撤销旧内部令牌；并发首次启动由锁控制。
2. `agent/opencode_mcp.py`：官方 Python MCP SDK stdio 服务，将具体工具清单和调用转给站点私有业务桥，不提供通用 SQL 或绕过授权的执行入口。
3. `agent/opencode_runtime.py`：OpenCode 负责对话和工具循环，本站复用现有工具参数、资源权限、预检、计划、动作确认和真实结果保存。后台查询 OpenCode 消息与工具事件，按稳定消息 ID 回写；保留业务/人工续接与停止。
4. 原生文件/命令默认只对本机管理员开放且逐次确认。命令或文件操作真正返回后才填写完成状态；非零进程退出码不能记为成功。拒绝、停止后的旧权限不可重放，未知业务状态阻止继续写入/计费调用。
5. `agent/runtime.py` 默认选择 OpenCode，保留显式 `AGENT_ENGINE=legacy` 回滚路径。旧执行器的 HTTP 脚本模型测试显式选择 legacy，新的默认路径通过真实 OpenCode HTTP/MCP 单独验收，不用假网关替代 OpenCode 后宣称接通。
6. `session.ts` 按会话保存请求状态和最近任务结果；响应式占位消息即时更新，随后以服务端 ID 校准。迟到历史不能覆盖新消息，切换项目/账号不能恢复旧状态；附件增量回调绑定发送时的会话。
7. 会话消息在同一秒产生时按 SQLite rowid 稳定排序，防止同时间戳导致显示顺序不稳定。
8. 保留 OpenCode MIT 声明，记录免费模型是独立的远程服务，赛事平台/原创性条件不能由软件许可证代替判断。
