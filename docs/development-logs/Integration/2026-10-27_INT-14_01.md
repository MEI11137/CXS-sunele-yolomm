# INT-14：本机文件夹工作区

- 日期：2026-10-27
- 实施工具：Codex。本轮根据用户提供的工作区弹窗截图及目录需求开发；没有伪称由 WorkBuddy 执行。
- 开发分支：`feature/opencode-agent`。未改动已发布 `haixun-v1.0` 标签，未推送或合并主分支。

## 问题与改动

原工作区仅保存名称、描述和项目要求，内嵌 OpenCode 使用会话私有临时目录，无法把用户指定的项目文件夹当作真实工作目录。

本轮增加真实磁盘/目录浏览、新建目录、创建工作区时选目录、旧工作区一次绑定、目录查询展示。Vue 组件按职责划分：WorkspaceSwitcher 管理创建/绑定表单，LocalFolderPicker 管理目录浏览与新建；Pinia 保存服务端工作区对象。

后端为 agent_project 增加可空 root_directory，保留历史数据和自动默认项目兼容。目录操作要求本机管理员与回环地址，拒绝非法/不存在/受保护路径及其他工作区的重叠目录。项目目录从服务端归属记录取得，不能由模型自由更换。

前端按账号角色展示目录入口：管理员创建文件工作区时必须选择目录；普通用户保留原有不绑定本机目录的工作区创建方式，避免新增限制阻断原有功能。表单请求失败显示具体错误，提交中不能重复保存；目录浏览的过期响应不会覆盖当前选择。

OpenCode 子进程 cwd、HTTP directory 参数都指向已绑定目录；私有凭据与缓存仍放后台状态目录。项目绑定后，引擎池撤销旧桥接令牌并重建实例；原生确认时再次核对当前目录，拒绝旧目录权限请求。目录缺失不会自动创建空替代目录。
