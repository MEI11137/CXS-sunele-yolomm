# INT-30：修复手动删除误报“项目不存在”

- 日期：2026-10-28；实施工具：Codex；分支：`feature/opencode-agent`。
- 用户反馈：数据集页面可正常显示，点击删除却提示“项目不存在”。

## 根因与改动

前端公共 HTTP 模块仅为 `/api/dataset`、`/api/model`、`/api/detection` 自动发送 `X-Project-Id`。INT-29 新增的手动删除预览/执行位于 `/api/agent/resources/lifecycle`，未被包含，后端收到空项目 ID，鉴权返回“项目不存在”。这与本机文件夹是否存在无关。

扩展公共传参规则，准确覆盖 lifecycle 根接口和子路径；预览、删除、恢复共用修复，其他账号级 Agent 配置接口不附带项目头。没有扩大资源权限，没有回退到管理员默认项目。

## 验证

- 数据库中用户项目仍为 active；绑定工作区文件夹确认存在。
- 新增前端回归：预览和恢复写入均携带当前项目头；取消删除只发送预览、不发送写入；账号级连接接口不携带项目头。复核相关前端5项测试通过，类型检查与145 modules构建通过。
- 新增后端真实路由隔离测试：缺少项目头时返回404，附带真实项目头返回200与正确资源、项目、依赖提示，1 passed。
- 真实浏览器点击人工修订版的删除入口，不再报“项目不存在”。当前项目存在用户正在运行的 Agent 任务，正确显示“项目有正在执行或待核实任务，请先完成或停止后再操作”；未绕过保护、未停止用户任务、未确认删除。
- 本轮不重载后端，避免打断用户任务；修复为前端公共请求传参，开发服务已加载，普通浏览器刷新后生效。
- 未删除用户数据、未训练、未提交或推送Git。

该项补充了INT-29遗漏的实际手动入口端到端请求覆盖；原先的工具确认与服务单测不能替代前端请求头检查。
