# INT-34：旧记录漏查修复与人工页面/Agent入口核对

- 日期：2026-10-28；实施工具：Codex；分支：`feature/opencode-agent`。
- 用户要求：解释页面残留旧记录为何内部Agent找不到、无法删除；再次核对人工功能是否都给Agent接了接口。

## 1. 根因与修复

- 只读核实：`detection_records`中的3条旧记录在agent_resource里用kind=record，后续6条用detection_record。两类同属当前项目、同一来源表；页面按source_table能看到旧记录，Agent资源查询原来按kind精确过滤，故错误地只看到新日期记录。
- `agent/resource_tools.py` 查询改为按当前项目+真实来源表；返回create_time、record_status、review_version、human_review_status、模型、反馈关联、is_deleted，日期/模型名也可搜索。
- `agent/permissions.py` 的kind过滤列表和{kind,id}解析兼容来源表别名；不更改旧资源ID、所有者、项目或权限。保留账号与项目授权，查到资源不等于授权写入。
- `workspace_list_resources` 项目概况排除业务表已软删除的记录，避免索引deleted_at为空却误认为记录仍活跃。
- 更新提示词：当前工具结果优先于旧聊天统计；include_deleted里is_deleted=true表示已删除；已有划分、反馈等工具不能因保留人工页面而拒绝调用。

## 2. 批量反馈工具

- 新增 `workspace_add_feedback`，补上识别记录页已有批量反馈与Agent之间的一次确认入口；原单条 `business_feedback_add_confirmed` 和闭环回流工具保留。
- 参数为1–50条真实record_id+expected_version，准备阶段核对当前项目、所有者、版本、未删除、人工确认及模型关联的可写源数据集。
- 卡片列出目标记录和实际来源数据集；执行核对动作ID、任务、请求键、prepared_id和参数，再重新预览校验。
- 复用既有 `add_batch_confirmed_records` / `add_confirmed_record`，没有另写反馈业务逻辑；逐项失败不能伪造整批成功，不自动训练、定稿或更改原标签。
- 前端卡片显示批量反馈数量，写入后发资源变更事件。删除仍保留具体真人确认。
