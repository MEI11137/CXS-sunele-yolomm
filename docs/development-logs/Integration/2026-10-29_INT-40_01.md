# INT-40：平台常规业务自动批准与文件删改确认

日期：2026-10-29；实施工具：Codex；修改版本：海巡智检v1.1；未提交、未推送。

## 用户要求与原因

此前grants/ToolSpec统一把write、critical和billable都作为逐次确认，原生文件权限模式却是另一套策略。选择“完全访问”后，检测和AI核查仍因写记录而每次生成卡片，助手因此说平台强制逐张确认。用户要求在保留人工标注决定与文件删改批准的同时，常规平台流转不要重复点击。

## 最终边界

| 操作 | request | assist / full |
|---|---|---|
| 查询与已授权只读检查 | 自动 | 自动 |
| 内置检测、AI核查、附件导入、数据集导入/新版本、反馈、草稿划分与定稿 | 具体确认 | 按服务器保存的会话策略自动执行 |
| 模型导入、用户明确要求的训练/发布 | 具体确认 | 同一内置策略执行，不能擅自启动训练或扩大任务 |
| 删除资源、最终人工标注提交/驳回等真人决定 | 确认 | 确认 |
| 原生已有文件修改/覆盖/删除 | 确认 | 确认；整批范围一次批准 |
| 原生项目内新文件、可识别新建命令 | 确认 | 按assist/full原生规则处理，未知影响仍确认 |
| 外部MCP、未知工具、跨项目写入 | 保留原授权 | 不因模式全局放行 |

复杂计划的方向确认仍独立存在，但不会再因每张图片写记录而请求逐张批准。

## 实现

- 新增agent/business_approval.py：只对白名单内、真实business来源、无外部server_id的工具读取实际会话permission_mode。模型参数、外部工具自述、项目文件内容均不能扩大权限。
- AgentRuntime增加默认关闭的策略钩子，只有网站OpenCode启用；原执行器及外部MCP确认策略不被全局关闭。
- 自动业务仍做资源权限、参数、服务端prepare、版本检查、原子执行权领取和request_key去重；action落审计但不发action.required、不进入等待用户点卡。跨项目实际写入目标仍回退具体卡片。
- 记录approval.source=session_policy、mode、human_clicked=false，动作决策事件为policy_approved，区别于人工点击confirmed。
- 自动执行失败标failed/unknown，不留假executing；未知或计费调用不自动重试。重复请求复用既有动作与业务记录，不重复付费。
- 旧常规业务待确认卡在下一次对话续接时按当前模式重新预检，刷新准备快照后沿同一请求键执行；不会在程序启动时自动调用真实AI。
- 文件权限检查增加“已有文件”核对：原生编辑、覆盖或涉及既有文件的写命令保留一次人工批准；只读及合规新建继续按模式处理。
- 同步权限选择器及OpenCode系统说明，不能继续声称“检测写数据库所以平台强制每张卡”；批量AI优先使用明确record_ids，保留人工复核入口和范围限制。
