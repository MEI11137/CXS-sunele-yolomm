# INT-38：复核结果两种去向与人工/Agent共用入口

日期：2026-10-29；实施工具：Codex；修改版本：海巡智检v1.1；分支：feature/opencode-agent（未提交、未推送）。

## 问题与最终行为

INT-37的简化页面只暴露了“反馈样本→草稿→另建数据集”，遗漏用户需要的“回原数据集”。已有巡检回流工具依赖run_id，不能用于全部手动记录；不能把创建反馈草稿描述为完成原数据集修订。

当前页面保留“我的数据集”和“处理复核结果”两入口。在处理页选择实际来源后，明确二选一：

- 回原数据集：生成一个包含原数据的新修订版。同内容RGB匹配原图后写入人工标注，保持原集合和样本键；多模态同时核对X图。真正新增的图片进入明确指定的train/val/test集合。原包保留，不自动训练。
- 另建数据集：只提取该来源下有效确认反馈，沿用原草稿、样本用途设置、检查定稿服务，不包含整个原训练集。

待整理版本可直接继续，旧tab/draft URL不变；手动ZIP导入、原比例划分、删除/回收站、模型管理入口保留。当前处理范围为所选来源池中的全部有效反馈，界面明确说明；巡检run的分组回流能力继续保留。

## 实现与接口

- 新增共享业务工具dataset.feedback_revision，在business_tool_specs、tool_handlers登记；OpenCode实际目录名business_dataset_feedback_revision，新增中文标题与系统工具使用说明。
- 手动API：POST `/api/dataset/<dataset_id>/feedback-revision/preview`，提交name、new_sample_split；POST `/feedback-revision`仅提交operation_id。强制核对当前项目、实际源资源权限、准备记录所属账号与对象。复用现有BusinessToolAdapter的预览、执行、持久记录与幂等request_key。
- 复用dataset_transform_service的源包扫描、私有副本、候选物化、YOLO校验及登记；补充修订合并模式，不另造训练或导入系统。manifest包含原包哈希、source dataset ID、反馈record ID、人工版本、标注哈希和每项实际写入键。
- 生成目录使用项目作用域datasets/candidates/<candidate_id>/dataset，包含data.yaml、RGB/X、标签和manifest；登记后的ZIP同样走既有工作区文件存储。不覆盖原始项目素材。
- 新修订版写入parent_dataset_id；手动修订及原手动比例划分成功后登记实际项目资源，避免新数据集存在但当前项目无法读取。
- 有效反馈必须仍人工确认、未删除且标注哈希与入池版本一致；修订执行时重新扫描并核对输入哈希及反馈版本快照。相同RGB的反馈结论冲突或X模态不一致则阻止，不能默默覆盖。
- 原反馈草稿路径也过滤失效与删除记录；Agent创建草稿前后校验同一反馈快照，避免确认后样本范围变化。
- 前端新增FeedbackRevision组件，展示反馈条数、修正张数、新增张数、总数与各集合数量，确认后生成；UI与Agent使用同一处理器。
