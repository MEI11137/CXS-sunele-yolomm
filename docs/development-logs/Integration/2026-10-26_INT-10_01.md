# INT-10：真实 MCP 连接、工具与授权

- 日期：2026-10-26（Asia/Shanghai）。
- 实际执行：Codex，接续 WorkBuddy 整合分支 `integration/haixun-v1`。
- 技能：技能包中的 `mcp-builder`、`vue-best-practices`、`webapp-testing`，以及已安装 `ponytail`。

## 原问题

`McpStore` 只有可注入工厂，没有实际传输；配置裁剪会丢失 arguments/credential_ref；工具指纹不含风险；通用 `mcp.execute` 不具备逐工具授权身份。前端只能展示清单。

## 本轮变更

1. 新增 `services/mcp_transport.py`，使用官方 Python MCP SDK `1.26.0`，支持 stdio 与 Streamable HTTP 的初始化、分页发现、调用、超时和关闭。
2. 仅用户在固定设置 API 配置 stdio 程序和参数；模型只看到已配置连接中的工具，没有 command/Shell 设置工具。
3. HTTP 使用个人 MCP Bearer 凭据；本机凭据通过 `MCP_API_KEY` 提供。凭据经原有个人加密存储保存，不借用大模型 Key。地址不允许嵌入凭据、查询参数或片段。
4. 增加连接 revision；配置更新清空工具发现缓存。指纹包含连接版本、工具 schema、说明及风险注解，旧放行随版本变化失效。
5. `agent/tools/mcp.py` 为每个外部工具提供单独的 `SOURCE_MCP`、server_id、version 和安全函数名。业务工具列表隐藏通用 MCP 调用/管理旁路。
6. 默认每次确认；人工核对过的具体非计费只读工具才可按项目放行。设置 API 校验当前连接、工具风险和版本，支持撤销。
7. 执行前再核对连接和工具版本；写入/计费结果未知不重发，对端自称幂等不构成重发依据。对端 `isError` 不记作成功。
8. 异常日志只记录安全错误类型，避免 SDK 异常包含请求凭据。回环 HTTP 地址直接连接，避免系统代理转发到错误位置。
9. 新增 `McpSettings.vue` 与受保护 `/api/agent/mcp/connections` 设置/发现 API。

## 检查结果

- `tests/test_int10_extensions.py`：真实本机 SDK 服务完成 stdio 和 HTTP 握手、发现与调用；3 passed。
- 真实装配用例：逐工具放行、风险变化后授权失效、旧工具调用拒绝、私有凭据不回传、无通用旁路。
- 浏览器：保存 stdio 服务 → 连接并发现 echo → 核对并放行 → 显示真实授权，已通过。
- SDK/PDF 先在 `.integration-deps/` 隔离验证，再补装到本机现用 `pvdetect` 环境；固定入口为 `requirements-agent.txt`。

## 明确边界

- 没有 OAuth 登录流程，也没有把旧 SSE-only 端点宣称为 Streamable HTTP。
- 每次操作建立并关闭 SDK 会话；没有跨调用常驻会话缓存。
- 外部服务程序仍按自身 OS/服务权限运行。站点目录授权约束内置文件服务，不能替第三方 MCP 实现 OS 沙箱；接入本机文件 MCP 时必须由使用者配置服务本身的允许目录。
- 测试的 echo 服务不访问文件、不连接大模型；测试通过不代表任意第三方服务的行为已经审查。
