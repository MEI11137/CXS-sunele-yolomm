# INT-25：回流生成的数据集保存到绑定工作区

- 日期：2026-10-28；实际开发与检查工具：**Codex**；分支：`feature/opencode-agent`。
- 用户要求检查生成新数据集的实测情况，并明确数据集文件也应出现在绑定的工作区。继续遵守“暂不训练”，未改人工标注或代替用户确认。

## 核查发现

INT-24 的真实修订版已在网站登记并保存在受保护的后台文件存储，但绑定目录中没有该修订版的 ZIP 和解压文件。这是工作区文件交付缺口，不能把“列表里有数据集”等同于“工作区已生成文件”。

`destination=new` 的独立样本数据集分支已有隔离业务测试，此前没有使用本轮真实数据执行。当前只有 `000091` 一条人工确认记录，另外两条仍为 pending；不能为演示凑数而代确认或把同一个样本复制为训练/验证两份。现行可训练新数据集规则仍要求明确且独立的 train/val 样本。

## 实现

- 新增 `services/project_dataset_export.py`，复用受保护数据集存储、项目权限和既有 ZIP 安全解压逻辑，无新增依赖。
- 内部 OpenCode 的既有 `workspace_route_reviewed_samples` 在数据集登记后自动调用导出：修订版与独立新建均保存至 `<项目绑定目录>/datasets/<数据集ID>/`。
- 目录包含 `dataset.zip`、`dataset/` 内的原始结构及 `export.json`（项目、数据集、原始归档 SHA256、文件哈希及解压根目录）。数据集 ID 用于防止名称冲突和路径注入。
- 完整暂存后在同一工作区内改名到最终目录；重复导出验证文件哈希并返回已有结果，不覆盖用户修改。输出目录不得沿符号链接或 Windows 重定向离开工作区。
- 确认卡预览增加输出目录和保存影响；项目绑定目录变化使旧计划失效。批次真实状态和完成消息记录可访问的文件路径。
- 登记成功而文件导出失败时，保留数据集 ID 和失败状态，不报告完成，不启动后续训练，也不换请求键重复导入。文件发现忽略导出暂存目录。
- 原手动上传功能、原始数据、已有模型均保持；没有另建 Agent 规划循环。
