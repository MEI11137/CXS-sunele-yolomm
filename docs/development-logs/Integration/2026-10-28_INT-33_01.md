# INT-33：批量反馈入口与候选草稿显示修复

- 日期：2026-10-28；实施工具：Codex；分支：`feature/opencode-agent`。
- 用户要求：识别记录支持勾选批量加入反馈，解释反馈去向；检查反馈草稿生成后仍显示0项，以及候选草稿与完整数据集比例划分的关系。

## 1. 批量加入反馈

- `RecordsView.vue` 在现有勾选工具栏增加“批量加入反馈所选（可处理数量）”。单条入口与批量入口共用处理函数。
- `feedbackSelection.ts` 只选当前记录列表中已勾选、human_review_status=confirmed、未入池、未删除的记录。已入池/未确认项不会被重新提交，不影响其他已选记录；后端仍核实最终资格。
- 一次确认列出实际目标记录及数量、跳过数量，明确每条回到其检测模型关联的原数据集反馈池；不改原数据集文件，不自动生成新版本或训练。
- 继续复用已有 `/api/detection/records/feedback/batch` 和 `add_batch_confirmed_records`，前端适配器去重并检查1–50条上限；请求保留当前项目头。
- 显示成功/失败数量、按实际返回数据集名称分组的结果和逐条失败原因，成功项清掉勾选，异常不自动重发。
- 将记录状态“已回流”明确为“已入反馈池”，提示需要后续生成草稿、划分并定稿，避免被理解为已覆盖原标签或自动合并原训练集。
- 内部Agent已有 `feedback.add_confirmed`、`workspace_route_reviewed_samples` 等入口继续复用相同反馈底层服务；本轮没有另加批量Agent工具或改变审批规则。

## 2. 草稿0项的原因与修复

- 后端 `/api/dataset/list` 未传 `record_kind` 时默认只返回formal；原数据集页面拿到这批结果后再筛draft，因此永远为空。数据库并没有丢失草稿。
- 新增可选查询参数 `PageQuery.recordKind`，RealAdapter传为record_kind；仅数据集页面显式选择all，并取首200条。模型页面默认查询保持formal，不让未定稿草稿混入训练选择器。
- 只读核实当前测试项目已有3个未删除草稿，分别8、3、3个样本。页面已显示“1个数据集·3个草稿”；最新8个样本均为paired、unassigned。
- 创建反馈草稿后读取返回ID并刷新，只有列表确实能找到该ID才提示生成成功并自动打开样本划分；列表不可见时明确提示核实，避免让用户反复生成。
- 草稿页补上读取中/读取失败状态，流程状态中文化；移除一直禁用的草稿“用于训练”按钮，定稿后在正式数据集列表使用。
- `DraftEditor.vue` 保留按样本分配train/val/test/excluded，新增关闭入口；没有改变样本划分和定稿服务。
- 本轮没有新增“草稿按比例自动划分”能力。正式数据集已有比例划分，草稿当前仍按样本手动划分或由内部Agent使用既有草稿划分工具。

## 3. 数据含义

1. 加入反馈池：登记已人工确认的检测记录与其来源数据集的关联，不直接改原数据集文件。
2. 生成反馈草稿：仅由人工反馈样本生成待划分草稿，不自动合并原训练集。
3. 样本划分并定稿：校验集合、标签和模态配对，成功后形成正式新数据集；训练另行启动。
4. 完整数据集比例划分：对全部源样本按比例生成新版本，是另一条已有入口。
