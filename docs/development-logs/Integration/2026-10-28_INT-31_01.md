# INT-31：单条/批量AI核查、识别记录删除与完整数据集划分

- 日期：2026-10-28；实施工具：Codex；分支：`feature/opencode-agent`。
- 用户要求：区分单条和批量AI核查，加入勾选批量方式；明确训练/验证/测试划分入口；追加识别记录单条与批量删除。

## 1. 核查范围与交互

- 核对原服务：单条接口按 URL 中的 record_id 查询，保存结果的 SQL 带 WHERE id，并没有隐式核查全部。旧前端用全局 busy 禁用整页且缺少目标提示，容易误解。
- 每行改为“仅核查此条”，只有当前目标显示“正在核查此条”；核查期间阻止再次提交。
- 记录列表加入复选框、全选当前页筛选结果、选择数量、“批量AI核查所选”、清空选择；最多50条，范围来自明确选择而不是整项目。
- 单条走原单条接口；批量走原 `/api/detection/records/ai-review/batch`，去重，说明调用本人模型API并确认数量；展示逐条失败结果，不自动重试付费请求。
- 原始状态码改为中文含义。已删除记录不能被新的单条/批量核查处理。

## 2. 记录删除

- 每行“删除此条”，勾选后“批量删除所选”；确认列出数量和目标，一次确认提交整批。
- 共用 `/api/detection/records/delete/batch` 与 `services/record_lifecycle.py`；服务端检查真实用户、当前项目、每条review_version。
- 同一事务预检所有对象再写入，任一归属/版本不符整批不写；仅把选中记录隐藏、递增复核及资源索引版本，保留图片、模型、数据集、反馈来源，可恢复。
- 内嵌OpenCode增加 `workspace_delete_records`：先查询真实ID及review_version，生成一张具体确认卡；必须实际用户确认，模型自报confirmed无效。写入后同步列表与复核页。
- 原复核页单条删除/助手恢复继续保留。

## 3. 完整数据集与反馈草稿划分

- 原划分仅在“生成反馈草稿 → 候选草稿 → 人工划分”中，且只包含人工反馈样本；不是对完整原训练集重新划分。
- 正式数据集每行加入“划分训练/验证/测试集”，可填新版本名和比例（默认80/10/10），先检查真实数量、重复内容泄漏、类别与模态配对，再确认创建。
- 新业务工具 `dataset.split` 组合调用既有 plan_from_dataset、build_candidate_from_dataset、register_candidate；手动新接口 `/api/dataset/<id>/split/preview` 与 `/split`，以及Agent，使用同一业务服务。
- 只创建并登记新版本，源数据集、模型保留；RGB、配套模态、标签一起划分，文件输出到绑定工作区。采用既有固定排序分配，不宣称随机/分层抽样。
- 比例须有限且合计1，训练/验证比例大于0；若取整后训练/验证为空，在预览明确阻止。
- 保存预备操作ID，执行核对真实操作者、项目、源数据集；同一预备操作使用固定请求键，重复请求不重复登记。
- 反馈草稿原流程保留，入口改为“样本划分/定稿”，编辑器显示本页train/val/test/unassigned/excluded数量、页内全选与排除选项。页面文案明确两种划分用途。
