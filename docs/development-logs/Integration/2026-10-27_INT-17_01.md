# INT-17：项目主对话、项目内业务、回收站与 T14

- 日期：2026-10-27
- 实施工具：Codex；工作分支 feature/opencode-agent。保留队友和前几轮改动，未推送或合并，未移动版本标签。
- 用户确认的布局：默认项目主对话；打开业务页面时，业务占主要区域，对话在右侧。
- 明确边界：T13 不执行；不修改旧 Agent 的模型循环，不另造规划/记忆/工具循环。

## 主要实现

1. `/projects/:projectId/chat/:sessionId?` 与各项目业务路由成为主入口，移除工作区选择器和工作区总览导航。左侧项目名称、会话及新建操作均直接进入对应项目；旧业务地址兼容重定向。
2. AppLayout 从路由确定实际项目，保护非法/已删除项目及不属于当前项目的会话。业务页面按路由重建，避免跨项目复用旧页面缓存。主对话复用原 AssistantPanel，打开业务页面时仍保留对话实例。
3. 新建项目支持初始附件上传；失败保留已创建项目并重试剩余文件，附件携带受保护资源 ID 进入对话。项目说明和要求与项目记录一次创建，避免二次 PATCH 失败遗留空项目。
4. OpenCode 新增三项 MCP 业务适配工具：当前项目资源清单、页面导航、本机项目文件上传登记。继续使用原有权限、预览、动作确认、操作记录和业务导入/检测工具；不模拟浏览器点击。
5. 项目/会话删除前显示名称和影响，采用软删除回收站，支持恢复。原始目录、业务数据及历史消息保留；后台执行中或待核实任务拒绝删除。被删项目/会话不能继续经旧桥令牌调用工具。
6. T14 只接当前 OpenCode 链路，敏感请求在模型调用前阻断并脱敏保存，输出脱敏扩展到常见凭据格式；保留普通问题、代码与文件工作。不是依靠聊天语句判断管理员身份。
7. 实查发现旧列表接口存在“管理员返回所有资源、普通用户只按账号过滤”的情况。本轮增加显式项目请求头及服务端校验；数据集、模型、发布模型和识别记录列表按项目过滤；手动导入、检测记录、反馈草稿及定稿登记到当前项目。
8. 修复文件资产与目录登记服务中 SQLite 上下文只提交但未显式关闭连接的问题，使用标准库 closing 在提交后及时关闭，避免 Windows 文件锁。
