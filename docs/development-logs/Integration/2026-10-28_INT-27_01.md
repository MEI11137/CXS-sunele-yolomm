# INT-27：复核画布平移与对话复核操作

- 日期：2026-10-28；实施与检查工具：**Codex**；分支：`feature/opencode-agent`。
- 用户要求：放大后能拖到目标区域；人工复核界面可用的操作也能通过语言与内部 Agent 交互完成。
- 用户进一步指示“继续”。沿用网站内部 OpenCode，不新建另一个 Agent；保留网页手动操作与项目文件规则。

## 1. 放大与拖动的修复

原画布只对外壳进行 CSS transform 缩放，滚动布局与可见大小不一致；拖动事件只处理框，没有独立的移动视野模式。

- 改为按真实缩放尺寸绘制 canvas，视口有实际可滚动宽高；适应窗口同时考虑宽度和高度。
- 加入“平移”按钮，支持空格＋拖动、鼠标中键拖动；选择模式拖动空白处也能平移，选中框仍可移动。
- Pointer Capture 保持拖出视口时的交互，取消拖动不生成框；ResizeObserver 适配窗口及助手栏宽度变化。
- 缩放保留视野中心；标注坐标仍相对原图归一化，不把视野位移写入框坐标。
- 框列表显示编号，可选择并定位；移动框、修改类别/严重程度与无缺陷操作可撤销。严重程度从原先仅界面状态补为随人工标注保存。

## 2. 页面与对话互通

前端发送当前项目/记录、真实复核版本、当前草稿、选中框编号及视图状态。服务端重新验证记录归属、类别与标注格式；这些材料明确标记为**尚未提交的页面上下文**，不是执行授权，也不意味着人工确认。

| 新工具 | 能力 |
| --- | --- |
| `workspace_review_state` | 读取真实记录、类别、归一化框、人工状态和版本 |
| `workspace_review_view` | 定位、缩放、适应窗口、选择框、平移/选择/画框模式、原图/结果/对照、前后项与撤销；不保存人工结论 |
| `workspace_review_record` | 准备标注草稿，提交用户明确指定的标注/无缺陷/驳回决定，删除或恢复记录；必须由用户确认具体卡片 |

用户可以说“放大到150%，切换平移”“选中第1个框”“把选中框改为大面积热斑，先改草稿”“这张没有缺陷”“删除这条记录”。坐标或类别不明确时先追问，不自行编造标注。

- 页面事件按会话、项目、记录及序号处理；页面未加载时短暂暂存，避免控制事件早到而丢失；切换项目不串操作。
- 草稿有独立版本。待确认期间用户继续改草稿时，旧卡片和迟到事件不能覆盖新草稿。
- 完成提交或删除后，复核页按真实业务状态刷新，不依赖助手文字假装成功。
- 界面仍保留提交、驳回、无缺陷、重画和手动删除入口。

## 3. 人工授权边界的明确调整

本次用户明确要求可通过语言操作复核界面，替代先前“人工复核只能通过原页面提交”的交互限制。调整后仍由人作最终决定：

1. Agent 读取实际版本并提出具体改动。
2. 确认卡列出项目、记录、版本、改动前后框及影响。
3. 用户本人确认后，由专用工具调用与原页面相同的 `submit_human_review`，以该用户身份写入；记录 `user_confirmed_conversation` 来源。
4. 工具验证服务端真实动作 ID、执行状态、任务、请求键、参数及 prepared ID，不能只传 `confirmed=true` 自行执行。
5. 新增 `agent_review_action` 记账与幂等检查；保留原复核审计，同时将操作快照写到工作区 `review/<记录ID>/<请求键>.json`。
6. 修改后再确认旧版本会拒绝。普通业务 `review.submit_human` 的原有入口限制保留，不泛化解除业务门禁；外部开发连接也没有获得代批准权限。

人工等待阶段允许发起这一专用复核卡，仍禁止跳过其他待确认写入。三档访问模式均不免除最终复核与删除确认。

## 4. 删除与恢复

- 删除采用记录隐藏状态，保留图片、原数据集、模型、人工标注和回流来源；记录版本递增，使旧确认失效。
- 网页和对话共用 `record_lifecycle.set_deleted`。普通列表不显示已删除记录，详情接口不将其当正常待复核项。
- 提供恢复入口及对话操作；已删除记录不能新增反馈或继续提交复核。
- 本轮队列排除已删除记录。删除并不等于人工确认；全部待复核项被删除时，不生成训练样本。

## 6. 验收中发现并补修

- 页面草稿使用毫秒时间戳，服务端最初将上限设得过小，造成“页面草稿版本无效”；改为 JavaScript 安全整数范围并增加真实量级测试。
- 原确认/拒绝接口会返回 `{action,...}` 或任务快照，前端却按裸动作读取，导致后台成功后显示“动作结构无法识别”。统一解析响应包，缺动作时读取实际动作接口核实。
- 原拒绝逻辑把任务重新设为 running，造成无执行器也显示运行中。改为等待输入（或仍有其他卡时等待确认），不自动推进后续写入，也不复活终止任务。
- 窄窗口下复核区域改为纵向排列，长文件名允许换行，画布限制在可视宽度；实际 460px 宽窗口复核页显示完整，150% 平移控件仍可使用。
