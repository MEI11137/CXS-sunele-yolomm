# C-02 第 2 轮：权限复核

## 发现与处理

- 项目权限回调原先只拒绝 `False`，现要求明确返回 `True`。
- 用户头像字段可伪造文件所有权，且修改旧头像会删除任意键；现要求头像来自该用户登记的 `avatars` 文件，头像字段不再作为旧文件读取授权。
- 普通用户可通过个人资料修改 `role`；现拒绝此字段。
- 图像增强、缺陷分析及识别结果保存可接收客户端任意文件键；现读取前检查有效账号和文件归属。旧识别记录删除只物理删除已登记且属于该用户的对象。
- 文件下载先复制到临时文件，再原子替换缓存；避免失败后复用部分模型文件。
- 本地 JWT 密钥以仅所有者可读写模式创建，并收紧已有文件的 POSIX 权限。
- 支持 `FILE_PUBLIC_URL`，供异机部署提供浏览器可访问的文件地址。
- 项目附件允许经 `file:read` 授权的项目成员读取及查看元数据；独立文件仍限上传者。

## 验证与余项

新增回归覆盖 `None` 权限结果、头像伪造、角色提升、图像入口跨账号读取、检测保存伪造、误删及项目成员读取。C-01/C-02 相关定向测试 46 项通过；最新后端全量回归为 196 通过、4 失败。4 项来自未修改的批量核查/反馈和个人大模型客户端测试，可独立复现，留待相应业务环节处理。旧业务记录缺可信创建来源，跨账号引用冲突会拒绝，但历史伪造数据仍需审计。项目统一权限提供者及业务表项目归属尚未接入，C-02 仍为部分完成。
