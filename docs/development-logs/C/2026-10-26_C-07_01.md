# C-07 开发（用户授权目录）

- 时间：2026-10-26（北京时间）
- 负责人：第三人业务工具任务，本轮由 WorkBuddy 在当前工作区执行
- 开发执行平台：WorkBuddy
- 分支 / 起点提交 / 接口版本：无 `.git` 元数据；业务工具接口 v1，新增 `directory.inspect`、`directory.search`、`directory.transform`
- 本次目标和原问题：
  - "让 Agent 直接读本地某个目录"最容易变成一句提示词或一个 MCP roots 声明——那不是权限。任务书要求：用户显式把目录关联到项目，后端按目录引用解析真实路径，并真正校验路径、链接与压缩包条目，防止逃出授权范围。
  - 旧代码里没有任何"授权目录"的概念，也没有把"后端进程能读"和"站点账号有权限"分开。
- 给 AI 的材料与关键词：任务书 C-07（用户显式关联目录到项目；按目录引用解析真实路径；搜索、读标签、配对、样本数、类别、重复、拆分检查；校验真实路径/链接/目录跳转/ZIP 条目；"后端能读"≠"站点账号有权限"；不能只是 MCP roots 或提示词）；`services/dataset_contract.safe_extract_dataset`（ZIP 条目逃逸防护已由其负责）
- 修改文件、具体业务及修改前后差异：
  - 新增 `services/authorized_directories.py`
    - `DirectoryStore(database_path)`：表 `authorized_directories(id, project_id, label, root, real_root, created_by, created_at, enabled)`；`register` 要求绝对路径并用 `resolve(strict=True)` 落 `real_root`，`get`/`list`/`disable` 只返回真实记录。**目录必须先登记**，工具不接受任意路径字符串。
    - `scan_dataset_tree(root, max_samples=50000)`：`os.walk(followlinks=False)` 遍历，产出 `{root, samples, sample_count, class_names, class_names_derived, issues, duplicates, leakage, splits}`。
      - 真实路径问题：`SYMLINK_SKIPPED`（遇到软链目录不跟随并记录）、`PATH_OUTSIDE_ROOT`（解析结果跳出根）、`CLASS_NAMES_MISSING`、`LABEL_MISSING`、`ORPHAN_LABEL`、`SCAN_TRUNCATED`（超上限时明说没扫全）。
      - 标签问题：`LABEL_ENCODING`、`LABEL_FIELD_COUNT`、`LABEL_NOT_NUMERIC`、`CLASS_ID_NEGATIVE`、`COORDINATE_OUT_OF_RANGE`、`BOX_NOT_POSITIVE`。
      - 样本键统一去掉模态目录前缀（`images/`、`images_edge/` 等），使 `images/train/a.jpg` 与 `images_edge/train/a.jpg` 归到同一 `train/a`，标签按 `labels/train/a.txt` 对齐；这一步同时修好了"从压缩包解出来的数据全部被判成孤儿标签"的问题。
      - `_duplicates_and_leakage` 用 RGB（或第一模态）文件的 sha256 找重复；跨 split 的重复即泄漏。
    - `inspect_directory(root, ...)`：在扫描基础上补 `RGB_MISSING` 与配对结果 `pairs`。
    - `search_directory(root, query, limit)`：返回 `{matches, truncated}`，只返回根内相对路径，**不回传根路径本身**，任何越界即拒绝。
  - `services/tool_handlers.py::DirectoryInspect` / `DirectorySearch` / `DirectoryTransform`：统一走 `_directory()` —— 先 `directory_store.get(directory_id)`，再用登记的 `project_id` 走 `_project_resource` 做动作裁决，项目不一致抛 `DIRECTORY_PROJECT_MISMATCH`。三个工具都实现 `recheck`，执行前重新解析目录与项目。
  - `services/business_tool_specs.py`：三个工具声明 `kind="directory"`，`max_samples` 上限 200000、`limit` 上限 500。
- 优化原因：把"能不能读这个目录"变成登记 + 项目裁决两件事，而非一句提示；扫描结果里所有路径都相对化，避免把本机绝对路径回传给 Agent 或前端；软链与越界一律跳过并记录，不静默跟随。
- 对第一人/第二人的接口、迁移和旧页面影响：
  - 第二人：需注入 `directory_store=DirectoryStore(db_path)`（未注入时三个目录工具不出现）；`resolve_resource` 需支持 `kind="directory"`；需裁决 `directory:read`、`directory:write`。目录登记必须由用户在自己的项目下发起，第二人不应代填路径。
  - 第一人：无旧接口改动。目录功能是新增能力，页面上还没有入口；若要给用户一个"关联目录"的界面，表单只需项目 + 标签 + 绝对路径三项。
  - 迁移：新增 `authorized_directories` 表，随 `DirectoryStore` 首次使用建表。
- 数据/文件保护方式和输出位置：测试在 `tmp_path` 下造目录树与软链，不读用户真实文件；返回结果不含绝对根路径；未复制或修改任何源文件（`directory.transform` 的输出另见 C-08）。
- 验证内容及结果：
  - `test_directory_inspection_reports_real_duplicates_and_symlinks`：split 计数正确、重复与跨 split 泄漏被识别、软链产出 `SYMLINK_SKIPPED`、返回内容里**不含**登记时的绝对路径。
  - `test_directory_search_cannot_escape_the_registered_root`：`../` 形式查询无法越出根目录。
  - 定向回归：C-01~C-06 全部用例保持通过。
- 未完成、风险和下一步：
  - 大目录（十万级）全量扫描有耗时上限，`max_samples` 触发时明确返回 `SCAN_TRUNCATED`，但没有进度上报。
  - Windows 下符号链接需要额外权限，`SYMLINK_SKIPPED` 在部分环境不会触发，测试用 `os.symlink` 失败即跳过该断言。
  - 目录内容的实时变化未做缓存失效策略，每次巡检都重扫。
