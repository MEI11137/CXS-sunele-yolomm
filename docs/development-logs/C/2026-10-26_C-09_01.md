# C-09 开发（文档解析与检索）

- 时间：2026-10-26（北京时间）
- 负责人：第三人业务工具任务，本轮由 WorkBuddy 在当前工作区执行
- 开发执行平台：WorkBuddy
- 分支 / 起点提交 / 接口版本：无 `.git` 元数据；业务工具接口 v1，新增 `document.parse`、`document.search`
- 本次目标和原问题：
  - 项目里没有任何"文档"概念：用户上传的 PDF/Word 只能当文件下载，Agent 无法引用原文。
  - 任务书要求引用必须能落到真实位置：PDF 要真实页序，Word 不能编造页码。
  - 本机 Python 环境**没有** `pypdf`/`PyPDF2`/`python-docx`/`fitz`（已逐个确认 import 失败），只能靠标准库实现。
- 给 AI 的材料与关键词：任务书 C-09（首版 PDF 与 DOCX；旧 .doc 提示转换；存原始文件、项目、版本、解析状态；文本/表格抽取、片段检索、多文档对比；PDF 保持真实页序；Word 用标题/段落/表格锚点不编页码；扫描页按个人模型能力或真实解析器处理并说明成本/失败/限制；引文与原文读取过个人权限；不做文档编辑/重排；不强制向量库）
- 修改文件、具体业务及修改前后差异：
  - 新增 `services/document_service.py`
    - 表 `documents(id, project_id, asset_id, title, original_name, format, status, page_count, block_count, sha256, error, warnings_json, created_at, updated_at)` 与 `document_blocks(id, document_id, block_no, block_type, text, page_no, paragraph_no, table_no, ...)`。
    - `describe_source(asset)`：按扩展名判定 `pdf`/`docx`/`doc`；`.doc` 返回 `supported: false` 且 `reason = "旧版 .doc 请先另存为 .docx 再解析"`，不尝试强解。
    - `parse_pdf(data)`：标准库实现 —— 正则扫 `n m obj … endobj`（容忍偏移错误的 xref）、识别 `/Type /Page`、按 `/Contents n 0 R` 或数组取内容流、`/FlateDecode` 用 `zlib.decompress` 解压、从内容流里提取 `(...)`、`[...]TJ`、`T*`/`ET` 文本。页号是**文件里的真实 1 基页序**；抽不出文本的页计入 `empty_pages` 并给"可能是扫描页"警告。
    - `parse_docx(path)`：`zipfile` + `xml.etree.ElementTree` 读 `word/document.xml`，按 `w:p`/`w:tbl` 产出 `heading`/`text`/`table` 块，块上带 `paragraph_no`（第 N 段）与 `table_no`（第 N 个表），并固定给一条警告"Word 文档没有固定页码，引用按段落与表格序号定位"。
    - `parse_document(database_path, asset, local_path, title, owner_id)`：按 `(project_id, sha256)` 去重，避免同一文件解析两次；状态 `ready` / `partial`（有扫描页）/ `failed`（解析异常，错误落 `error` 列并保留 `warnings`）；块写 `document_blocks`。
    - `get_document`、`search_document(database_path, document_id, query, limit)`：片段检索返回 `block`/`block_type`/`page_no`/`paragraph_no`/`table_no`/`excerpt`/`citation`；`failed` 状态文档明确拒绝检索而不是返回空。
    - `_citation`：PDF → `第 N 页`；Word 表格 → `表格 N`；Word 正文 → `第 N 段`。
  - `services/tool_handlers.py::DocumentParse`：解析 `.pdf`/`.docx` 上传资产，`.doc` 抛 `ToolRefused("UNSUPPORTED_DOCUMENT", CONVERT_HINT)`；`recheck` 重新解析资产与项目，项目不符 `DOCUMENT_PROJECT_MISMATCH`。
  - `services/tool_handlers.py::DocumentSearch`：要求 `document_id` + `query`（不支持跨全部文档的裸查询，避免越权聚合），项目校验同上。
  - `services/business_tool_specs.py`：`document.parse`（`kind="project"`）、`document.search`（`kind="document"`，`query` 与 `document_id` 均必填）。
- 优化原因：引用必须可核对 —— 页号来自真实页序，不给 Word 编页码；扫描页不假装解析成功；旧 `.doc` 明确要求转换而不是猜；不引入向量库依赖，用真实文本块检索。
- 对第一人/第二人的接口、迁移和旧页面影响：
  - 第二人：需裁决 `document:create`（解析）与 `document:read`（检索/引文），并保证引文读取走同一裁决；`resolve_resource` 需支持 `kind="document"` 与 `kind="project"`；`document.parse` 需要 `storage_client` 与文件资产网关。
  - 第一人：新增能力，无旧接口改动；若要展示，`documents.status` 可直接映射为"解析中/可用/部分可用/失败"。
  - 迁移：新增 `documents`、`document_blocks` 两张表，随服务首次使用建表。
- 数据/文件保护方式和输出位置：只解析用户项目内的上传资产；原文不复制到公共目录；`document_blocks` 只存抽取出的文本片段，测试用自造的最小 PDF/DOCX，不涉及真实文档。
- 验证内容及结果：
  - `test_pdf_pages_keep_the_real_page_number`：构造两页 PDF，第二页命中片段的 `citation == "第 2 页"`，`page_no == 2`。
  - `test_docx_uses_paragraph_and_table_anchors_not_page_numbers`：段落引用为 `第 2 段`，表格块 `table_no == 1`，且不含"页"字。
  - `test_legacy_doc_is_refused_with_a_conversion_hint`：`.doc` 抛 `UNSUPPORTED_DOCUMENT`，文案含"另存为"。
  - 定向回归：C-01~C-08 全部用例保持通过。
