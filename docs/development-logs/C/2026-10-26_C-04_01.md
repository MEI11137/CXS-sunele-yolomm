# C-04 开发（检测执行与 AI 复核工具化）

- 时间：2026-10-26（北京时间）
- 负责人：第三人业务工具任务，本轮由 WorkBuddy 在当前工作区执行
- 开发执行平台：WorkBuddy
- 分支 / 起点提交 / 接口版本：无 `.git` 元数据；业务工具接口 v1，新增 `detection.run`、`detection.get_state`、`review.ai`
- 本次目标和原问题：
  - 检测与 AI 复核原来只有页面路由，Agent 无法调用；页面单条复核还会自己读全局密钥，违反"用第二人的每用户模型客户端"要求。
  - 页面批量复核不去重，同一记录重复提交会重复付费；失败项的处理散落在路由里。
  - 多模态检测缺第二模态图时，旧代码会退化成单模态继续跑，产出不可信的结论。
- 给 AI 的材料与关键词：任务书 C-04（用已发布模型做真实检测；AI 输出只是疑似/建议；批量逐项成败；付费动作不盲重试）；`detection_service.execute_detection`；`ai_review_service.review_detection`；`batch_review_service.run_batch_ai_reviews`；C-03 的模型发布语义
- 修改文件、具体业务及修改前后差异：
  - `services/tool_handlers.py::DetectionRun`
    - `prepare` 解析图片资产 → 取项目快照 → 读模型行，产出阻断项：`MODEL_PROJECT_MISMATCH`（模型不在文件所属项目）、`MODEL_NOT_PUBLISHED`（`status != 3`）、`MODALITY_PAIR_REQUIRED`（多模态模型没给第二模态图）、`SECONDARY_PROJECT_MISMATCH`（两张图不在同一项目）；单模态模型误传 `secondary_asset_id` 时记进 `ignored_arguments` 而不是静默丢弃。
    - `execute` 阻断时抛 `ToolRefused("DETECTION_BLOCKED")`；正常路径把资产 materialize 成本地文件后调 `execute_detection`，注入 `detector_loader`/`detector_predictor`（测试与特殊部署可替换），返回 `record_id`、检测框、原图/结果图/第二模态图地址，并在 `finally` 里删除临时文件。
    - `recheck` 重新解析资产与项目，防止准备后被移到别的项目。
  - `services/tool_handlers.py::ReviewAI`
    - `prepare` 要求 `model_client_factory` 可调用（否则该工具根本不出现），按去重后的记录出预览：每条记录的 `review_version`、人工/AI 复核状态、`billable: true`、`impact` 文案。
    - `recheck` 与 `execute` 都重新比对每条记录的 `review_version`，被他人复核过即 `ToolConflict`（需要重新准备，避免用过期版本覆盖别人的结论）。
    - `execute` 调 `run_batch_ai_reviews`，`client_factory=adapter.model_client_factory`（当前用户自己的模型客户端），`review_runner=review_detection`；`is_admin_user=True` 是因为授权已在每条记录上由策略服务裁决过，批量器不应再套页面那套"仅本人"规则。
    - 输出 `requested/succeeded/failed/items` 逐项结果；描述符声明 `billable=True`、`supports_cancel=False`。
  - `services/tool_handlers.py::_records`：按输入顺序去重（`dict.fromkeys`），保证一次付费复核只对每条记录调用一次。
  - `services/business_tool_specs.py`：`detection.run`（`kind="project"`）、`detection.get_state`（`kind="record"`）、`review.ai`（`kind="record"`，`record_ids` 1~50 条）。
- 优化原因：检测必须用真实已发布模型、必须真实配对；AI 结论只作为建议，不写成人确认；付费动作去重且失败项不自动重试；每条记录的人工结论不被并发覆盖。
- 对第一人/第二人的接口、迁移和旧页面影响：
  - 第二人：必须注入 `model_client_factory(principal) -> 用户自己的模型客户端`，否则 `review.ai` 不出现；`resolve_resource` 需支持 `kind="record"` 与 `kind="project"`；需裁决 `record:read`、`record:review`、`model:read`、`file:read`；`detector_loader` 建议注入真实 `load_detector`。
  - 第一人：页面 `/api/detection/*` 全部保留；单条与批量 AI 复核改为走同一份个人模型连接，请求/响应字段不变；旧的"降级成单模态"行为在工具层被禁止（页面路径未改动）。
  - 迁移：无新表，复用 `detection_records`。
- 数据/文件保护方式和输出位置：检测临时文件写在 `work_dir/detection` 并在 `finally` 删除；测试用假 predictor，不加载真实权重；未触碰运行中的图片与记录。

  - `test_ai_review_is_one_paid_call_per_record_with_per_item_results`：输入两条重复 ID，`requested == 2`、假客户端 `calls == 2`。
  - 定向回归：C-01~C-03 全部用例保持通过。
