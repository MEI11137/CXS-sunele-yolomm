# C-05 开发（人工复核、反馈回流与草稿定版）

- 时间：2026-10-26（北京时间）
- 负责人：第三人业务工具任务，本轮由 WorkBuddy 在当前工作区执行
- 开发执行平台：WorkBuddy
- 分支 / 起点提交 / 接口版本：无 `.git` 元数据；业务工具接口 v1，新增 `review.submit_human`、`feedback.add_confirmed`、`draft.create_from_feedback`、`draft.assign_splits`、`draft.finalize`、`draft.get_state`
- 本次目标和原问题：
  - 人工复核只有页面入口，Agent 既不能提交复核，也不能读到"这条记录到底是不是人工确认过"。
  - 反馈回流散在 `feedback_dataset_service` 与 `dataset_draft_service` 之间，调用方很容易把"AI 建议"当成"人工确认"送进草稿。
  - 草稿生成时缺少"只含已确认反馈、不自动混原训练集"的显式约束。
- 给 AI 的材料与关键词：任务书 C-05（红/改/增/删/确认无缺陷；持久化真实人工确认状态与版本；只有人工确认样本可回流；草稿默认只含已确认反馈；人工拆分 + 真实条件才定版）；`review_service.submit_human_review`；`feedback_dataset_service.add_confirmed_record`、`create_feedback_dataset_draft`；`dataset_draft_service.assign_draft_samples`、`validate_draft_for_finalization`；`dataset_finalization_service.finalize_draft`
- 修改文件、具体业务及修改前后差异：
  - `services/tool_handlers.py::ReviewSubmitHuman`：`prepare` 对比记录当前 `review_version` 与 `expected_version`，不一致直接给 `RECORD_VERSION_CONFLICT` 阻断（写库前就能看到）；`execute` 调 `submit_human_review`，版本冲突映射 `RECORD_VERSION_CONFLICT`、标注非法映射 `ANNOTATION_INVALID`，成功后回读真实 `human_review_status`、`review_version`、标注条数。
  - `services/tool_handlers.py::FeedbackAddConfirmed`：`prepare` 要求 `human_review_status == "confirmed"`，否则 `NOT_HUMAN_CONFIRMED` 阻断；`execute` 调 `add_confirmed_record`，业务拒绝映射 `FEEDBACK_REFUSED`，返回 `sample_id`/`created`（重复提交返回 `created: false`，不产生第二份）。
  - `services/tool_handlers.py::DraftCreateFromFeedback`：`prepare` 统计"该数据集下人工确认过的反馈样本数"，为 0 时 `NO_CONFIRMED_SAMPLES` 阻断，并在 `impact` 里写明"原训练集不会被自动混入"；`execute` 调 `create_feedback_dataset_draft`。
  - `services/tool_handlers.py::DraftAssignSplits`：只有 `workflow_status == "draft"` 可改（`DRAFT_NOT_EDITABLE`），拆分被服务拒绝时映射 `DRAFT_SPLIT_REFUSED`（含训练/验证泄漏）。
  - `services/tool_handlers.py::DraftFinalize`：`prepare` 直接跑 `validate_draft_for_finalization`，不满足条件时把原因放进 `blocked_reasons`（`FINALIZE_CONDITIONS_UNMET`），并预览类别、各 split 计数、样本总数；`execute` 调 `finalize_draft`，返回新 `dataset_id`。
  - `services/tool_handlers.py::DraftState`：读草稿真实 `workflow_status`、各 split 计数。
  - `services/business_tool_specs.py`：六个工具按 `kind="record"` / `kind="dataset"` / `kind="draft"` 声明，`review.submit_human` 的 `annotations` 用逐字段 schema 校验（`class_name`/`class_id`/`bbox`），最多 500 条。
- 优化原因：把"是否人工确认"提前到写库前的可见结论；把"只有确认样本能回流"变成硬约束而不是调用方自觉；草稿默认不含原训练集，避免训练集被静默污染。
- 对第一人/第二人的接口、迁移和旧页面影响：
  - 第二人：`resolve_resource` 需支持 `kind="record"`、`kind="dataset"`、`kind="draft"`，且 `record` 的 `version` 必须是 `review_version`（否则并发保护失效）；需裁决 `record:review`、`record:feedback`、`dataset:read`、`dataset:update`、`draft:read`、`draft:write`。
  - 第一人：页面 `/api/detection/records/<id>/human-review`、`/feedback`、`/feedback/batch`、`/api/dataset/drafts/*` 全部保留，字段与文案不变；工具层是对同一批服务的封装，不引入第二套写入路径。
  - 迁移：无新表；沿用 `feedback_samples`、`dataset_drafts`、`dataset_draft_samples`。
- 数据/文件保护方式和输出位置：草稿与定版的工作目录在 `work_dir/feedback-draft`、`work_dir/finalize`，测试用临时目录；未触碰已有草稿与数据集。
