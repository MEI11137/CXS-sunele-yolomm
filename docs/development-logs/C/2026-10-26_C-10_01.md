# C-10 开发（外部 MCP 接入）

- 时间：2026-10-26（北京时间）
- 负责人：第三人业务工具任务，本轮由 WorkBuddy 在当前工作区执行
- 开发执行平台：WorkBuddy
- 分支 / 起点提交 / 接口版本：无 `.git` 元数据；业务工具接口 v1，新增 `mcp.save_connection`、`mcp.test_connection`、`mcp.discover_tools`、`mcp.execute`
- 本次目标和原问题：
  - 任务书要求"用户自己配置/启动/停止本地程序或网络 MCP，凭据走第二人的独立凭据存储，站点只做发现与受裁决的执行"。原来完全没有 MCP 概念。
  - 最大的风险是"连上了就当能调"：连接成功 → 模型拿到工具清单 → 想调哪个调哪个。这是把授权交给了外部服务。
  - 执行失败时不能假装知道结果；非幂等的写操作尤其不能自动重发。
- 给 AI 的材料与关键词：任务书 C-10（用户手动配置/启动/停止；凭据独立存储；发现工具列表与参数结构；记录工具版本与连接状态供第二人筛选授权；只执行第二人程序裁决过的请求；不能因连接成功就自动调全部工具；外部能力/版本变化通知第二人重新裁决；声明写入/计费/可查询/幂等/可取消；未知外部状态不自动重发；不能让模型装服务、改启动配置或提交任意系统命令；网站不能假装沙箱化外部进程）
- 修改文件、具体业务及修改前后差异：
  - 新增 `services/mcp_registry.py`
    - 表 `mcp_connections(id, owner_id, name, transport, endpoint, command, arguments_json, credential_ref, enabled, status, error, tools_version, updated_at, …)` 与 `mcp_tools(connection_id, name, description, schema_json, writes, billable, idempotent, cancellable, effects_declared, version)`。
    - `McpStore(database_path, *, transport_factory=None, secret_store=None)`：
      - `save` 只存 `credential_ref`（凭据引用），**不存凭据本身**；`stdio` 必须有 `command`（否则 `MCP_COMMAND_REQUIRED`），`http` 必须有 `endpoint`（`MCP_ENDPOINT_REQUIRED`）。
      - `_transport`：连接被禁用或未配置传输时抛 `McpUnavailable("MCP 传输尚未配置：本机服务需由用户自行准备，网站不代为安装或启动")`。**本层不安装、不启动、不改系统配置**。
      - `discover`：调 `transport.list_tools()`，按 MCP `annotations` 推导 `writes`（无 `readOnlyHint` 即视为写）、`billable`、`idempotent`、`cancellable`，并标 `effects_declared` 表示外部是否真的声明了副作用；`tools_version` 取 `[[name, schema]]` 的 sha256 前 16 位，与上次比较给出 `changed`。
      - `get_tool`：只返回**最近一次发现**里的工具，未发现过的名字查不到。
      - `invoke`：必须先 `get_tool` 命中；调用异常时，若该工具是"写且非幂等"，抛 `RuntimeError("外部工具执行结果未知，未自动重发: …")` → 上层记 `unknown`；其余抛 `McpUnavailable`（可安全重试的读或幂等写）。
  - `services/tool_handlers.py` 四个 MCP handler：
    - 全部先 `_workspace(adapter, principal, <本工具自己的 spec>)` —— 每个工具用**自己声明的动作**做裁决，不会因为 `mcp:manage` 过了就放行 `mcp:execute`。
    - `McpSaveConnection` 支持 `credential_ref`，`kind="workspace"`。
    - `McpTestConnection` / `McpDiscoverTools` 为 `effect="read"`；`McpExecute` 为 `effect="write"`、`supports_cancel=False`。
    - `McpExecute.prepare` 在**准备阶段**就校验工具是否在发现清单里，不在则 `MCP_TOOL_UNKNOWN`（不消耗一次外部调用），并把 `writes`/`billable`/`idempotent`/`cancellable` 全部放进预览，`impact` 写明"该调用由外部服务执行，网站不为其实际访问权限背书"。
  - `services/business_tool_specs.py`：四个工具声明 `kind="workspace"`（保存）与 `kind="mcp_connection"`（测试/发现/执行）；`mcp.execute` 参数含 `tool_name` 与 `arguments`。
- 优化原因：把"连接"和"授权"彻底分开——连接只说明通道通，能不能调由第二人按工具粒度裁决；工具清单与版本落库，第二人能据此筛选与重新裁决；非幂等写操作失败不重发，宁可报 `unknown`。
- 对第一人/第二人的接口、迁移和旧页面影响：
  - 第二人：需注入 `mcp_store=McpStore(db_path, transport_factory=..., secret_store=...)`（未注入时四个 MCP 工具不出现）；需裁决 `mcp:manage`（配置/测试/发现）与 `mcp:execute`（执行）两个动作；`resolve_resource` 需支持 `kind="workspace"` 与 `kind="mcp_connection"`；凭据必须由第二人的凭据存储持有，本层只见引用。
  - 第一人：无旧接口改动；本地服务由用户自行准备与启动，站点不代管。
  - 迁移：新增 `mcp_connections`、`mcp_tools` 两张表，随 `McpStore` 首次使用建表。
- 数据/文件保护方式和输出位置：测试用假 transport（内存对象），不启动任何外部进程；`mcp_connections` 只存 `credential_ref`；未写入任何真实凭据或外部系统。
- 验证内容及结果：
  - `test_mcp_connection_is_configured_then_discovered_then_executed`：保存 → 离线测试报"本机服务需由用户自行准备" → 上线测试 → 发现工具（`preview["tool"]["writes"] is False` 的只读工具）→ 执行成功。
  - `test_mcp_write_tool_failure_is_reported_as_unknown`：非幂等写工具失败 → 操作 `unknown`，外部只被调用 **1 次**（没有自动重发）。
  - `test_mcp_execute_requires_the_policy_to_allow_it`：策略拒绝 `mcp:execute` 时，即使 `mcp:manage` 通过也拒绝执行。
  - 定向回归：C-01~C-09 全部用例保持通过。
- 未完成、风险和下一步：
  - 真实 MCP 传输（`stdio`/`http` 客户端）未实现：本环境没有 `mcp` 依赖，`transport_factory` 由第二人按实际 SDK 注入。当前状态是"接口与裁决齐备、传输待接"。
  - `cancel` 一律 `False`：外部工具的取消能力取决于外部服务，本层不承诺。
  - `tools_version` 变化目前只在上报里标记 `changed`，没有主动推送给第二人；需要通知时由第二人在 `discover` 之后读该字段。
  - 用户"停止本地服务"由用户在系统侧操作；本层没有也不应有杀进程的入口。
- 提交 / PR：当前源码副本无 Git 元数据，未生成。
