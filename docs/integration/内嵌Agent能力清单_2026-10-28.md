# 内嵌海巡助手：当前能力、接口与扩展位置

核对日期：2026-10-28。以当前 `feature/opencode-agent` 工作区源码为准。底层继续使用 OpenCode 1.19.4，没有另建执行器。本清单区分“已有实现”与“真实场景验收”，不承诺每个命令、文件格式或外部 MCP 都已实测。

## 1. 驳回的含义与接口

- 驳回只更新原识别记录的 `human_review_status=rejected`，保留原图、检测结果及审计，不复制图片、不移动文件、不创建第二条识别记录。
- 已驳回项从普通待复核队列移出，在同一项目的“识别记录 → 已驳回”分类查询。这是同一批记录的筛选，不是独立文件夹。
- 从识别记录显式打开已驳回项可以重新标注/确认无缺陷并提交；重复驳回按钮禁用。
- 页面接口：`POST /api/detection/records/<record_id>/human-review`，请求包含 `decision: rejected`、`annotations: []`、`expected_version: 当前版本`，使用当前登录账号鉴权。
- Agent 专用工具：`workspace_review_record`，参数 `operation: rejected`；先读 `workspace_review_state` 获取真实版本，展示专用确认卡，用户确认后执行。
- 两个入口共用 `services/review_service.py::submit_human_review`。同一版本、相同已驳回结论的重复调用不会增加记录版本和复核审计；旧版本请求仍返回冲突。
- 驳回不等于“确认无缺陷”。前者不参与新增反馈回流，后者是人的明确负样本结论。先前已经导出的数据集版本也不会因后来驳回自动改写。

## 2. 工作区文件操作

当前本机管理员账号、绑定项目文件夹后，可使用 OpenCode 原生工具：

| 能力 | 实现与边界 |
| --- | --- |
| 列文件、查文件名、搜索文本、读文件 | `list / glob / grep / read`；以当前项目目录为工作目录，项目内明确只读操作无需逐张授权 |
| 新建/修改文本文件 | 原生 `edit`；适合 YAML、JSON、TXT 标注、说明文档等，按权限模式显示差异或自动执行 |
| 创建目录、复制、移动、重命名、批量整理 | 原生命令工具实际使用 PowerShell；复杂命令和删除/移动/重命名仍需确认 |
| 合并、转格式、打包、批量计算 | 可以提出命令或脚本，能否完成取决于本机现有程序、Python 包及权限；未知影响的命令需确认，工具真实返回后才算完成 |
| 删除文件 | 明确列出目标与范围，整批操作申请一次确认；不能把业务记录删除和物理文件删除混为一谈，普通文件删除不保证可回收 |

权限模式已经实现：

- 请求批准：项目内明确只读工具/命令自动处理，文件写入请求确认。
- 帮我批准：可判定的项目内普通原生编辑自动批准，普通写命令仍按预检确认。
- 完全访问：可判定的项目内普通编辑和普通写命令自动批准。
- 三档都保留删除、清空、移动和无法判定影响的命令确认。当前命令策略也将重命名归入需要确认的操作。

原生命令/编辑入口当前只向本机管理员开放。工作目录和确认策略不是操作系统沙箱；经确认的命令实际继承运行后端的本机账号权限，不能解释为“完全访问时所有命令都自动运行”。

**文件修改不等于网站已导入资源。**例如在文件夹里复制一份 ZIP，并不会自动增加数据集条目；修改原目录 TXT，也不会自动覆盖已经登记的数据集版本。要让网站使用新数据，应继续调用附件登记、校验、导入/生成新版本等业务工具。

## 3. 网站功能操作

| 用户目标 | 当前已有工具/入口 |
| --- | --- |
| 查询当前项目数据集、模型、记录、附件 | `workspace_list_resources`；各资源业务状态工具 |
| 让网站打开某个功能 | `workspace_open_page`，支持人工复核、数据集、模型、图片巡检、识别记录、资料、扩展；可带草稿 ID、数据集页签或记录状态。打开页面不代表执行里面的动作 |
| 按名称/状态查业务资源或回收站 | `workspace_query_resources`；返回真实业务 ID、资源版本和状态，回收站必须显式 include_deleted |
| 删除/恢复数据集、模型、草稿 | `workspace_manage_resource`；与网页删除/恢复共用服务，移入回收站且保留文件，检查在用数据集、已发布/训练中模型及其他活动任务，需具体确认卡 |
| 单条/批量删除识别记录 | `workspace_delete_records`，明确1–50条ID和review_version，一次具体确认，任一版本冲突整批不执行，保留业务文件；原workspace_review_record单条恢复仍可用 |
| 完整数据集按比例重新划分 | `dataset.split`（Agent名称business_dataset_split），明确新版本名及train/val/test比例；真实预览后生成并登记新版本，原数据集不变；不是人工反馈草稿划分 |
| 把项目中的 ZIP、PT、图片或资料交给网站 | `workspace_attach_file` 登记后继续走对应业务工具；原手工上传保留 |
| 导入数据集、导入权重 | `dataset.import`、`model.import_weight` |
| 数据集检查、类别映射、过滤、划分策略、候选版本 | `directory.inspect/search/transform`、`dataset.transform/register_candidate`；受授权目录和实际参数约束，输出候选，不默改来源 |
| 图片检测和 AI 核查 | `detection.run`、`review.ai`；AI 看图核查要求当前连接确实支持图片 |
| 自动找数据与权重并开始闭环 | `workspace_discover_inputs`、`workspace_start_inspection_loop`；确认本轮范围、置信度等计划后推进，人工决定处停下 |
| 复核页缩放、平移、选框、切换视图、撤销 | `workspace_review_view`，前端接收工具事件 |
| 按用户指令修改草稿、提交标注/无缺陷/驳回 | `workspace_review_record`；具体卡片由人确认，不由模型自行作出人工结论 |
| 隐藏/恢复识别记录 | 同一个 `workspace_review_record` 的 `delete/restore`；保留业务文件，需确认 |
| 反馈、数据集草稿与定稿 | `feedback.add_confirmed`、`draft.create_from_feedback/get_state/finalize`；`workspace_route_reviewed_samples` 按人明确给出的去向与划分执行回流。`workspace_draft_samples` 读取实际样本 ID，`draft.assign_splits` 已按最新用户要求向 Agent 开放，按明确指令并经确认划分，不代表 AI 确认标注 |
| 增量训练、查状态、对比、发布/撤销发布 | `training.start/get_status`、`model.compare/publish/unpublish`；需依赖就绪、参数完整及具体业务确认，本轮没有实际训练 |
| PDF/Word 文本解析、检索和引用 | `document.parse/search`；现有 PDF、DOCX 解析，不代表支持所有扫描件/OCR，也不代表能任意编辑 Word/PDF |
| 已授权外部 MCP | 通过扩展设置连接、发现并授权后调用具体工具；新增服务配置不能由模型自行批准 |

业务层的 `dataset.import` 等名称在 Agent 清单中会映射为 `business_dataset_import` 等安全工具名，再由内置海巡 MCP 交给 OpenCode 使用。

## 4. 当前不能直接承诺的操作

- “网站所有按钮都能对话操作”：只有已经注册的工具才支持；没有通过鼠标自动点任意按钮的通用浏览器工具。
- 清空整个项目全部业务数据、级联删除依赖、物理清除文件：没有开放这类通用动作；数据集/模型/草稿已有独立可恢复删除，不得用 PowerShell 删注册目录或写 SQLite 代替。
- 通过聊天自行创建/删除项目、管理 API Key 或授权新 MCP：没有开放对应模型工具；现有 UI 入口保持使用。
- 自动修改网站前端源码：目前 Agent 工作对象是项目数据文件，系统规则禁止修改网站源码。前端开发仍在 Codex/开发工具中进行。
- 自动知道尚未接入的按钮、猜类别/坐标/训练参数、把 AI 建议记为人工确认：不支持。

## 5. 可直接尝试的说法

1. “查看当前工作区，列出候选数据集和 PT 权重，先不要训练。”
2. “读取 data.yaml，检查 RGB 和红外图片是否配对，报告缺失文件，不修改原数据。”
3. “把这批数据复制到新候选目录，按我给的类别映射合并；先展示输出位置和处理计划。”
4. “打开当前项目的已驳回记录。把我指定的这条重新打开人工复核。”
5. “选第 1 个框，类别改为大面积热斑，只改草稿。”
6. “这些已人工确认的样本回原数据集，生成新版本，暂不训练。”

## 6. 后续扩展建议（尚未实施）

优先接通常用业务缺口，而不是再增加一个 Agent：

1. 本轮已完成：业务资源名称/状态查询、已驳回筛选导航、数据集/模型/草稿删除恢复、实际草稿样本查询和对话划分。
2. 后续可以细化原始项目数据与已登记数据之间的差异预览；已有转换、候选导出与新版本登记工具继续复用。
3. 后续可以增加网页可查看的动态能力清单，显示当前账号/项目下可用与未就绪工具及失败原因。

2026-10-28 INT-29 更新：项目业务动作采用“页面入口＋Agent 工具入口”同一套服务；不因为保留手动页面就拒绝 Agent 执行已有工具。人工核查的最终判断仍由人负责。复核原图/结果图支持滚轮缩放（50%–300%，每次滚轮事件10个百分点），保留缩放按钮与百分比，并以鼠标位置为缩放锚点。

## 7. 代码核对位置

- `web-flask/agent/opencode_engine.py`：原生工具配置、工作目录和进程。
- `web-flask/agent/native_policy.py`：命令与编辑的三档审批策略。
- `web-flask/agent/project_tools.py`：资源查询、打开页面、附件登记。
- `web-flask/agent/review_tools.py`：复核专用工具、确认授权与审计。
- `web-flask/agent/inspection_loop.py`：闭环工具与人工衔接。
- `web-flask/services/business_tool_specs.py`、`tool_handlers.py`：业务工具与实际实现。
- `web-flask/agent/tools/mcp.py`：逐项暴露已授权外部 MCP。

工具存在不意味着每次模型一定正确调用；实际可用清单还按账号、项目权限、依赖和连接状态过滤。
