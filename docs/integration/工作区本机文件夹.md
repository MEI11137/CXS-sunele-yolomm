# 工作区绑定本机文件夹

## 如何使用

1. 使用本机管理员账号访问 `http://127.0.0.1:5173/projects`。
2. 点击左侧「新建项目」。
3. 填写名称，点击「选择文件夹」；可以浏览 C/D/E 等磁盘、进入已有目录，也可输入绝对路径并点击「前往」。
4. 如果需要新目录，在目标父目录填写「新文件夹名称」，点击「新建文件夹」。该按钮会立即创建真实目录，即使随后取消工作区创建也不会删除它。
5. 点击「使用此文件夹」，检查路径后创建工作区。
6. 将需要处理的项目文件放进这个目录，在右侧 Agent 输入任务。例如：「先列出当前项目的文件，检查 images 与 labels 的对应关系，不修改原文件」。
7. 输入框下方选择会话权限模式。项目内读取自动执行；「帮我批准」还允许明确文件修改，「完全访问」还允许预检通过的常规文件命令。删除、清空、移动与未知命令仍需确认。整批删除合在一次命令中说明范围，一次批准；业务导入、训练、发布仍走原有业务确认。

旧工作区没有自动指定磁盘目录。在它的工作区菜单中点击「绑定本机文件夹」，选择目录后点击「确认绑定」。已绑定目录不能直接改绑；需要不同项目目录时，新建工作区。同一目录及上下级目录不能重复分配给不同工作区。

## 实际存储范围

- 绑定目录是 OpenCode 真正使用的项目文件目录；同一工作区的不同会话使用同一个项目目录。
- Agent 的配置、凭据、缓存、会话运行状态放在后台私有状态目录，不写入项目目录。
- 网站数据库、原有数据集、权重、图片、上传附件和训练产物仍按已有业务存储方式保存。**绑定目录不会搬迁这些文件，也不代表网站上传入口已切换存储位置。**
- 本轮实现的是可选择的真实 Agent 文件工作区。需要 Agent 整理的本地数据应放入所选目录；整理结果若要成为网站中的可训练数据集，仍需通过现有导入/校验/确认流程注册。修改本地标签不能替代人工复核或直接改变已注册业务版本。

## 权限与限制

- 浏览、新建、绑定本机目录仅限本机管理员，并要求目录接口及绑定请求来自回环地址。
- 业务资源仍按网站用户和项目隔离。项目要求、聊天内容和工具参数不能自行修改目录绑定。
- 磁盘根目录、账号根目录、系统目录、站点后端及私有配置等目录不允许作为项目根目录。路径必须存在且为绝对路径；不接受网络共享/设备路径。
- 目录消失或解析位置发生变化时，拒绝继续使用，不悄悄切回其他目录。历史未绑定的工作区保留原有会话临时目录行为。
- 自动批准受当前会话模式及确定性程序预检约束，无法判断影响时降为人工确认。**工作目录和 OpenCode 的路径权限不是操作系统沙箱**；人工批准的 Shell 仍有运行后端的 Windows 账号权限，批准前要核对完整命令。此版本不适合作为公开多用户的任意命令执行服务。
- 这不是源码编辑权限入口；网站前端继续由开发工具在源代码项目中修改。

## 接口与代码

- `GET /api/agent/local-folders?path=...`：空路径列出可用磁盘，其余路径列出子目录。
- `POST /api/agent/local-folders`：`{parent, name}`，显式新建一层目录，不覆盖既有目录。
- `POST /api/agent/projects`：新增可选 `root_directory` 字段。
- `PATCH /api/agent/projects/<id>`：仅允许历史未绑定项目一次性绑定。
- 项目查询和列表返回 `root_directory`；SQLite 通过幂等 ADD COLUMN 补列，原数据保持不变。
- `agent/project_folders.py` 负责目录校验和本机浏览；`OpenCodeRuntime._engine` 从已校验的所属项目取目录；`OpenCodeEngine` 将它同时用于子进程 cwd 与每次 HTTP 请求的 directory 参数。
- 引擎池检测目录变化后关闭旧进程、撤销旧业务桥令牌并创建新实例；旧目录中的权限卡不能直接用于新目录。
