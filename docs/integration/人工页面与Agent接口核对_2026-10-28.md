# 人工页面与内嵌海巡助手接口核对

日期：2026-10-28；2026-10-29 INT-38补充反馈去向。实施工具：Codex。范围：当前 `feature/opencode-agent` 工作目录中的实际Vue页面、Flask业务接口和OpenCode工具注册表。本文区别“有HTTP接口”“已暴露给模型”和“本轮真实执行验收”，不把三者混为一谈。

## 一、本次旧记录不能被Agent定位的原因

当前项目的旧记录索引类型为 `record`，新记录为 `detection_record`；它们实际来自同一张 `detection_records` 表。原 `workspace_query_resources` 按kind精确匹配，遗漏旧记录；原页面按source_table筛选能看到旧记录，因此双方数量和日期不一致。

修复内容：查询按真实来源表兼容别名；`{kind,id}`引用和按kind过滤列表同样兼容；查询返回create_time、record_status、review_version、模型和反馈池关联；include_deleted明确返回is_deleted。普通项目概况排除已软删除的识别记录。没有改旧记录所属项目、ID或真实业务内容。

## 二、项目业务页面对应能力

工具在MCP客户端中通常带 `haixun_` 前缀；下表使用服务端名称。所有写工具须通过实际权限、预览、版本和用户确认，不能用SQL或文件删除代替业务调用。

**2026-10-29 INT-40确认策略更新：**上表/旧说明的“确认”不再等于所有业务都要求点击。当前网站OpenCode在服务端保存的assist/full模式下，固定白名单内的检测、AI核查、导入、反馈、草稿划分/定稿和新版本流转复用真实预检后按会话策略自动批准，保留请求键及结果日志。request模式仍严格确认；外部MCP、未知工具、跨项目写入、删除与最终人工复核决定不自动放行。原生已有文件修改、覆盖、删除仍须批准。复杂计划的方向确认不等于逐图确认；训练或发布只能在用户明确要求下调用。自动模式不会替用户作出标注真值，也不会自动重做付费或结果未知的调用。

| 页面/人工操作 | Agent入口 | 范围与限制 |
| --- | --- | --- |
| 打开项目业务页面、指定记录或草稿 | `workspace_open_page` | 当前会话项目，真实ID；不代表已提交业务操作 |
| 查询数据集/模型/草稿/识别记录 | `workspace_query_resources`、`workspace_list_resources` | 支持旧类型别名、搜索、分页和显式包含删除项 |
| 从绑定工作区寻找数据集与权重 | `workspace_discover_inputs` | 读取真实文件候选，不能把文件存在等同于已登记 |
| 本地文件登记成附件 | `workspace_attach_file` | 当前绑定目录；本机管理员入口，校验类型和路径后复制，保留原文件 |
| 网页手工上传文件 | 原有上传接口 | 保留；Agent可接收已登记附件引用，也可使用上一项登记本地文件 |
| 导入ZIP数据集 | `business_dataset_import` | 复用格式、标注、模态配对和类别校验 |
| 数据集变换/整理/合并 | `business_dataset_transform`、`business_dataset_register_candidate`、`business_directory_transform` | 依赖受授权源与规则，输出新候选；不宣称任意数据都能无冲突合并 |
| 完整数据集按比例划分 | `business_dataset_split` | 预览真实数量和配对后一次确认，保留源数据集，输出到工作区 |
| 文件来源、属性及重复只读检查 | `business_dataset_inspect_samples` | 实际样本路径、标签路径、尺寸/大小/格式、文件与像素SHA256；支持search/page/page_size、指定当前项目record_id。检查字节/像素/旧JPEG转换重复、跨集合重复、标签内容差异，不自动删除。对应GET `/api/dataset/<id>/inspect`，网页和Agent共用处理器 |
| 数据集/模型/草稿删除与恢复 | `workspace_manage_resource` | 可恢复删除；受引用、训练中或已发布等阻止条件照常生效 |
| 导入PT权重并关联数据集 | `business_model_import_weight` | 真实权重可加载校验；不自动发布 |
| 发布/撤销发布 | `business_model_publish`、`business_model_unpublish` | 本人项目与模态范围；列清替换影响；不影响系统默认或其他项目 |
| 新旧模型对比 | `business_model_compare` | 读取真实指标及比较条件，不保证新模型更好 |
| 图片巡检 | `business_detection_run` | 已发布模型与匹配RGB/X附件；支持明确置信度 |
| 批量检测与自动闭环 | `workspace_start_inspection_loop`、`workspace_inspection_state` | 一次明确本轮范围；人工核查停下，不能自动作出人工结论 |
| 单条/批量AI核查 | `business_review_ai` | record_ids为用户指定范围，最多50；使用个人模型连接，失败不自动付费重试 |
| 读取/调整复核页面 | `workspace_review_state`、`workspace_review_view` | 定位记录、视图、缩放、平移等界面状态；读取不等于确认 |
| 改框、改类别、无缺陷、提交、驳回 | `workspace_review_record` | 按用户指示准备草稿；最终人工决定须用户在页面或具体卡片确认，AI不得自行标为人工确认 |
| 单条/批量删除识别记录 | `workspace_delete_records` | 真实ID+review_version，一次卡片；版本冲突整批停止，保留文件和反馈来源 |
| 恢复删除的识别记录 | `workspace_review_record`的restore | 核对真实当前版本；可恢复删除，不重做检测 |
| 单条指定目标反馈 | `business_feedback_add_confirmed` | 只收人工确认记录，校验目标数据集 |
| 按来源数据集批量加入反馈 | `workspace_add_feedback`（本轮新增） | 1–50条，一张确认卡；逐条报告；只入池，不修改原标签、不自动建版本 |
| 生成反馈草稿 | `business_draft_create_from_feedback` | 仅反馈样本，不自动合并原训练集 |
| 回原数据集生成修订版（通用入口） | `business_dataset_feedback_revision` | 来源数据集ID、新名称、新图集合；不要求巡检run_id。保留原包和原划分，内容相同的RGB替换标注并核对配套模态，真实新增图片按指定集合加入；一次确认，不训练。对应网页POST `/api/dataset/<id>/feedback-revision/preview`和`/feedback-revision`，两者共用业务处理器 |
| 查询草稿真实样本ID与划分 | `workspace_draft_samples`、`business_draft_get_state` | 分页读取，不能猜样本ID |
| 保存训练/验证/测试/排除划分 | `business_draft_assign_splits` | 划分可通过对话完成，不属于需要人亲自作出的图像真值判断 |
| 检查并定稿 | `business_draft_finalize` | 后端检查划分、类别、配对及独立集合条件，失败不报成功 |
| 巡检批次按指定记录分组回原/另建 | `workspace_route_reviewed_samples` | 依赖真实闭环run_id及来源；按用户选定记录和去向生成，产物写工作区。普通手动记录不伪造run_id，使用上一通用修订入口或反馈草稿→划分→定稿 |
| 增量训练与状态 | `business_training_start`、`business_training_get_state` | 明确父模型/数据集/参数；同时一项训练；不自动重做 |
| PDF/Word资料解析、检索 | `business_document_parse`、`business_document_search` | 附件与文档按权限引用，给出处；扫描件能力有明确限制 |
| 工作区文件读取、搜索、编辑、命令 | OpenCode原生read/glob/grep/edit/write/bash等工具 | 按当前模式及路径政策执行；删除或未知影响仍确认，不能绕过业务数据库权限 |

## 三、不能宣称已与Agent完全对应的页面操作

| 操作 | 当前实际状态 |
| --- | --- |
| 识别记录“导出本页CSV” | 前端已有导出；尚无等价的专用Agent导出工具。原生文件工具可在明确范围下另行生成文件，但不能把它冒充为已经对接该按钮的业务工具 |
| 项目新建/重命名/绑定目录/删除/恢复 | 已有受保护的HTTP页面接口；当前项目业务Agent没有对应的一整套管理工具。尤其当前会话所属项目的删除涉及会话终止，需要单独设计 |
| 会话新建/切换/删除/恢复 | 前端和HTTP已支持；目前没有给内部Agent完整暴露。会话历史不等于任意可读取其他会话或账号 |
| 主题切换、布局宽度、复制、滚动、模型下拉交互 | 由前端控制，未提供逐项Agent工具；不影响实际业务工具能否执行 |
| API Key保存/删除，模型连接配置 | 本人设置页入口；不把Key作为聊天参数交给模型。Agent可报告连接缺失并引导打开设置 |
| MCP连接配置/新目录授权/自动放行授权/权限模式扩大 | 本人设置页明确操作；不向模型暴露自助扩权工具。已经授权的MCP工具才会进入实际调用目录 |
| 最终人工标注真值与删除批准 | 必须保留真人决定；专用工具可以提出改动，模型不得替用户点击批准或伪造人工身份 |

因此，本轮结论是：**项目检测—核查—人工衔接—反馈—数据集—训练发布的主要业务都有工具入口；不能说网站所有UI按钮都已完整Agent化。**剩余普通功能与保留本人操作的安全设置已在本节分别列明，不再仅凭存在HTTP路由就标为“已接通”。

## 四、验收证据与限制

- INT-40：真实业务服务＋隔离模型替身验证assist/full各3张检测与1次批量核查无pending卡、无action.required事件，重复同一批AI请求不增加调用；默认request保留卡；伪装外部工具、删除、最终人工复核不能放行；未人工确认样本不能进入反馈；旧AI卡续接使用新预检与同一请求键；自动失败不遗留executing状态。完整512项及38子测试通过，补充失败处理后定向7项通过。未使用真实付费API测试此策略。
- INT-39：修复旧上传JPEG95重编码破坏原文件SHA256的真实问题；当前反馈记录57d02d2d-b2ce-4041-85f1-c7eb5b0904ec匹配`images/train/000084.jpg`，共享回流代码只读核验为修正1、新增0、总163，原包哈希不变。普通回流与巡检run分组回流共用身份规则；同名或多候选不自动覆盖/追加，配套模态同样核对。新上传记录持久保存原始文件属性，检测兼容转换只写工作区临时副本。完整503项及38个子测试通过，补充上传兼容及GET接口后15项定向测试通过；网页模拟展示来源判定、标签路径、重复检查，未执行真实回流或付费核查。
