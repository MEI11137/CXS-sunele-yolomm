# 项目对话主界面与 OpenCode 扩展

## 使用方式

1. 访问 http://127.0.0.1:5173/projects。左侧只列项目和各项目的会话历史，底部为回收站与个人设置。
2. 点击项目名称，直接进入该项目的主对话；点击历史会话直接打开所属项目和对应会话。不再额外操作工作区选择器。
3. 当前项目顶部保留人工复核、数据集、模型管理、图片巡检、识别记录、资料与手册、扩展与连接等手动入口。打开业务页面后，对话保留在右侧，可拖动宽度或收起。
4. 新建项目可选择本机目录并同时上传初始 ZIP、PT、图片、PDF/DOCX/Markdown。文件先登记为项目附件，不会未经校验就当作已导入数据集或已发布模型；进入对话时附件已带好引用。
5. 之后仍可从数据集、模型、巡检页面手动上传，或在聊天中选择附件。对于已在项目文件夹里的材料，可直接告诉助手文件路径，由受控工具确认后上传登记。
6. 示例指令：「列出本项目的资源」「打开人工复核页面」「把项目目录里的 data.zip 登记并检查，再引导我导入」。助手缺少类别、模态等必要信息时仍需追问；人工标注与划分仍由用户提交。

## 项目与会话删除

左侧项目/会话旁的 × 先打开确认弹窗。确认后移入回收站，可恢复；不会递归删除本机目录、数据集或权重文件。删除项目会使其业务资源不可通过正常项目入口使用，恢复项目后重新可用。

系统资源项目不能删除；其他账号的项目或会话不能删除或恢复。有正在运行、等待业务完成或状态不明的任务时，先停止或核实任务再删除。

同名项目以及同一根目录的绑定目前保留唯一性：项目在回收站时，优先恢复原项目；需要新项目时使用不同名称与独立目录。

## 架构边界

- OpenCode 继续负责模型调用、工具循环和原生文件能力。未增加第二套规划、记忆或模型执行器，也未修改旧 Agent 的模型循环。
- 新增 `workspace_open_page`、`workspace_list_resources`、`workspace_attach_file` 三项网站适配工具，通过已有私有 MCP 桥暴露。
- 页面工具只生成当前项目的导航事件，不提交人工复核或触发训练。前端只接受当前项目的受支持路由，不因重新打开历史对话而重放旧导航。
- 本地上传工具只读取已绑定项目目录内的文件；确认卡记录路径、大小及 SHA256，确认后文件发生变化会拒绝上传。注册的附件继续交给原有业务工具处理，不重复实现数据集导入、检测或训练。
- 原页面请求携带 `X-Project-Id`，服务端重新检查账号、项目状态和实际资源归属。项目 ID 不是授权凭据；手动上传、图片检测记录、反馈草稿和定稿均登记至实际当前项目。
- 个人模型连接仍是账号级配置，由其所有项目共用。网站上传附件和训练产物仍沿用业务文件存储，不因新界面而自动搬迁到项目目录。
- 原生权限按当前会话的三档模式处理；项目内明确只读自动执行，删除和未知命令仍确认，批量删除单次批准当前整批操作。业务确认独立保留，工作目录不等于操作系统沙箱。

## T14 与 T13

T13 暂不执行：正常问答、代码、解释与项目文件工作继续可用，不因用户说“我是管理员”而判定为攻击。

T14 在当前 OpenCode 入口拦截直接索取服务端凭据、私有提示词等请求。误粘贴的 API Key/登录令牌不会发送给模型，入库显示脱敏内容；输出与工具事件也做已知密钥和常见令牌格式的脱敏。文件、文档及工具输出不能代替权限或人工确认。

这些检查属于辅助防护，不能声称正则能识别全部提示注入。真正的执行边界仍是服务端身份、项目资源校验、目录范围、禁用项目自带配置及人工确认。
