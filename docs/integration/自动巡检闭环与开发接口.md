# 网站内部自动巡检闭环与开发接口

实施日期：2026-10-27。实施工具：Codex。运行引擎仍是网站内部的 OpenCode。

## 用户流程

1. 创建项目并绑定独立本机文件夹，把数据集目录/ZIP 和 PT 权重放入该目录。原有手动上传、导入权重、巡检与复核入口全部保留。
2. 对海巡助手说明数据集、权重、检测范围、图片数量和置信度。候选不唯一时由用户选择；助手通过 `workspace_discover_inputs` 查真实文件。
3. `workspace_start_inspection_loop` 生成一张整轮确认卡，包含：实际项目、源文件、类别索引、RGB/X 配对、准确图片清单、置信度、AI 调用次数、模型发布影响。确认之后才执行。
4. 后台自动登记附件、导入数据集、导入权重、发布自用模型、逐图检测、调用本人模型看图核查。相同来源再次巡检可复用已核实的数据集/权重；也可指定本项目已登记的 `model_id` 使用迭代模型。
5. 有疑点或核查失败的记录进入本轮人工复核队列，页面显示 AI 建议，可查看真实 RGB 与配套模态图。AI 判定一致不会冒充人工确认，也不会自动回流。
6. 用户在原复核页修正标注、确认无缺陷或驳回；也可以通过语言让助手准备具体改动，并由用户本人点击复核确认卡提交。助手查询数据库中的真实状态；聊天里的“已完成”或 AI 判断不能代替用户提交/确认。提交核实完成后，在会话中询问回流去向。
7. 用户按记录指定“回原数据集”或“另建数据集”。回原数据集表示创建修订版，保留原始数据，按图片内容匹配替换原样本标签；另建只包含选中的人工确认样本。新数据集需明确 train/val/test 划分，至少有独立训练及验证样本，不能复制图片伪造验证集。
8. `workspace_route_reviewed_samples` 出一张具体回流确认卡，确认后自动生成数据集版本。允许分组、分批指定去向；已回流记录不能重复分配。驳回项不进入训练样本。
9. 回流计划可选择增量训练参数及是否发布。训练复用已有训练服务及本机单任务锁；完成后读取真实对比及验证条件，再按已确认的发布范围处理。条件不同不能宣称效果一定更好。

这是一项由内部 Agent 调用的确定性业务批任务，不是新增另一套规划模型。外部开发接口不负责完成上述流程。

## 业务工具

| 工具 | 作用 |
| --- | --- |
| `workspace_discover_inputs` | 当前项目目录中查找数据集和权重候选，只读 |
| `workspace_start_inspection_loop` | 整轮预览与一次批准，后台检测和 AI 核查 |
| `workspace_inspection_state` | 查询真实批次状态、逐项结果及复核入口 |
| `workspace_route_reviewed_samples` | 按真实人工结果生成数据集、可选训练与发布 |
| `workspace_review_state` | 读取当前项目复核记录、类别、归一化标注和版本 |
| `workspace_review_view` | 只调整页面缩放、平移、框选择及视图，不保存人工结论 |
| `workspace_review_record` | 按用户明确指示准备草稿、提交复核、删除或恢复，必须确认具体卡片 |

首次巡检参数示例（模型不得自行添加 approved 等授权字段）：

```json
{
  "project_id": "真实项目ID",
  "dataset_path": "Hotspot_MM",
  "weight_path": "hotspot-mm-fp3p4/weights/best.pt",
  "confidence": 0.25,
  "sample_limit": 3,
  "secondary_modality": "ir"
}
```

使用已登记的模型时，提供 `model_id`，省略 `weight_path`；图片来源仍通过 `dataset_path` 明确指定。普通用户继续使用原有页面；本机文件闭环工具只对本机管理员开放。

回流参数示例：

```json
{
  "project_id": "真实项目ID",
  "run_id": "真实批次ID",
  "destinations": [{
    "record_ids": ["已人工确认的真实记录ID"],
    "destination": "original",
    "name": "热斑人工修订版",
    "training": {"epochs": 10, "batch_size": 4, "publish": false}
  }]
}
```

省略 `training` 即不训练。另建数据集使用 `destination: "new"`，另提供 `splits: {"记录ID": "train或val或test"}`。未划分的现场新增样本回原数据集，也必须明确其划分。

回流生成的两类数据集均登记到网站并保存到绑定的工作区：`datasets/<新数据集ID>/dataset.zip`、`datasets/<新数据集ID>/dataset/`（图片、配套模态、标签、配置）以及 `export.json`。确认卡给出输出父目录，实际完成消息和批次 `state.datasets[].workspace_export` 给出完整路径。原文件保留，用户修改后的已有导出不能被再次导出覆盖；文件保存失败时保留已登记 ID，停止后续训练并如实报告，不能把网站登记成功当作全部完成。

## 执行与恢复

### 项目文件位置

实际网站要求业务操作使用已绑定的项目目录。网页上传与 Agent 工具相同：上传、数据集 ZIP、权重及检测文件在 `artifacts/<分类>/`；项目临时处理在 `.cache/`；完整回流版本在 `datasets/<ID>/`；转换候选在 `datasets/candidates/`；训练权重、日志与指标在 `training/<模型ID>/`，不随临时解压清理。没有绑定目录时提示用户绑定，不回退到后台目录。

账号凭据、数据库、头像和引擎私有状态由网站保管。历史对象通过受保护的旧链接别名读取工作区副本，保留原文件用于回退；未变更文件访问权限。任意 Shell 仍是本机进程，工作目录不等同于 OS 沙箱。具体实现、实测范围及限制见 [INT-26](../development-logs/Integration/2026-10-28_INT-26_01.md)。

- 批次、不可变计划、源文件哈希、业务操作 ID、附件登记、逐项检测及核查结果保存在 `agent_inspection_run`。
- 不修改其他通用工具的审批规则；只有这两个整轮工具以完整卡片取得其范围内的批准。删除及未知命令仍遵守现有三档权限规则。
- 文件改变、连接改变、复用资源改变、发布影响扩大都会拒绝旧计划。实际权限在业务执行时再次检查。
- 独立图片失败不影响其他独立图片；依赖导入失败则停止。AI 失败明确记录，不自动重做付费调用。业务结果未知也不通过换请求键重做。
- 刷新或关闭侧栏不取消后台工作。停止只停止后续步骤，不能声称已撤销正在进行的调用。
- 后端重启将活动批次标记中断，保留操作记录，不自动重启训练、写入或付费核查。人工等待批次保留，继续读取真实复核结果。
- 复核 URL：`/projects/<项目ID>/review?flow_id=<批次ID>`；只显示该批次需要人工检查的记录。
- 状态读取：`GET /api/agent/inspection-runs/<批次ID>`，必须经过本人站点鉴权与项目权限检查。

## DeepSeek 模型名称与视觉检查

DeepSeek 官方的 `deepseek-flash` API ID 对应 V4.1 Flash。界面在官方地址下显示友好名称，同时保留实际 API ID；不把自定义接口的同名模型擅自认定为官方模型。

本次发现旧视觉探测 PNG 数据损坏，错误被泛化成“模型不支持图片”。改为标准库生成具有正确 CRC 的 PNG；认证、网络、无效图片和不支持能力分别反馈。已使用当前官方连接验证真实图片请求成功。

参考：[官方发布说明](https://api-docs.deepseek.com/news/news260910/)、[官方视觉接口](https://api-docs.deepseek.com/guides/vision/)。

## Codex / DeepSeek Harness 开发连接

接口仅用于开发诊断，不替代内部 OpenCode 闭环。未修改 Codex/Harness 的全局配置，也未自动为它们创建访问令牌。

由本机管理员通过站点已有登录认证调用：

- `POST /api/agent/dev/connections`，正文 `{"project_id":"真实项目ID","source":"codex"}` 或 `source: "deepseekharness"`。
- 返回独立开发会话与一次性可见的令牌，有效期 4 小时。数据库仅保存令牌哈希。
- `DELETE /api/agent/dev/connections/<连接ID>` 撤销连接，仍需原管理员的站点认证。

令牌只用于以下本机接口，不能作为普通网站登录令牌使用：

| 接口 | 作用 |
| --- | --- |
| `GET /api/agent/dev/state` | 当前获授权项目的独立开发会话、消息与任务 |
| `POST /api/agent/dev/message` | 发送 `{"text":"诊断内容","request_id":"唯一请求ID"}` |

外部消息带“开发调试消息 · 来源”标记；同一请求 ID 不会重复发起模型调用，参数改变会拒绝。开发会话已有运行任务、人工等待或批准卡时不插入另一轮任务。接口没有批准操作、提升权限、提交人工标注或删除资源的能力。连接被撤销、过期、账号停用或失去管理员权限后不可继续使用。
