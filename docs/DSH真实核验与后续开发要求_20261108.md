## 4. 执行顺序与阶段目标

### 阶段 A：固定环境与同步版本

1. 记录正在运行的源码目录、端口、数据目录、普通账号项目根路径、连接器和公网构建；不打印密码、Token、API Key。
2. 保留本机／服务器各自配置，不把测试 API Key、账号或绝对磁盘路径硬编码到源码。
3. 测试期间只有主执行者重启。重启前检查正在执行的 Agent／上传／训练任务，避免人为制造网络失败后误判产品缺陷。
4. 把最新必要构建发布到原 WorkBuddy 应用；若发布失败，报告真实原因，不无限循环等待截图。
5. 对本机和公网各做一次登录、导航、列表查询与小文件请求对照，记录真实时序，定位具体失效层。

**完成标准：** 同一后端与明确的前端构建可复测；普通账号进入正确 v1.7 工作区，无串版本、串账号、串 API。

### 阶段 B：多模态真实业务闭环（最高优先级）

1. 使用真实 Hotspot_MM RGB＋IR 配对样本和匹配权重。优先用已导入的 10 样本小数据集，选 3 对执行，不上传 223 MB。
2. 核对真实权重结构、主辅模态、类别与映射；映射不明时用简短自然语言询问，不能猜测、无声改类别。
3. 通过**站内 Agent 对话**从工作区寻找数据集／权重，读取属性，导入或复用已登记对象，启动选定样本检测。不能仅用手工上传 image 资产或外部 HTTP 脚本证明 Agent 可用。
4. 数据集内的 project_file／样本应能经受支持的业务路径进入检测；不应强迫用户逐张上传已存在于服务器的数据。
5. 使用当前用户有效连接进行真实 AI 核查；验证 RGB 和配对 IR 都进入支持图片的模型请求。Key 不输出、不迁移到前端，不无声改成全局／其他用户连接。
6. 自动打开对应人工复核队列或详情，解释待人工检查内容；**人工判断和标注结论留给人**。另建明确 QA 记录验证提交接口时，不冒充真人结论。
7. 核对任务状态、每条记录来源、样本身份、模型版本、置信度、核查结果与错误信息。失败不得写成完成，不遗漏部分失败。

**完成标准：** 公网普通账号发起的站内 Agent 操作真实跑通；每个阶段有任务／记录 ID 和真实结果；人工环节以待人工状态停下，或用明确标记的 QA 夹具单独验证后续接口。

### 阶段 C：双画布标注与数据回流

1. 双模态只需两张原始配对图，RGB／IR 均可独立标注；不回退为仅 RGB 可编辑，也不添加重复的第三张图。
2. 每张图可滚轮缩放、按钮缩放、平移、适应窗口、选择／移动／缩放框、画框、删除框和撤销；显示实时倍率。缩放不得改标注坐标。
3. RGB、IR 使用各自原图尺寸与坐标，记录当前编辑模态；保存草稿、刷新、切换记录后两套框均正确。辅助图有缺陷而 RGB 无框时不能丢掉 IR 标注。
4. 检查保存、提交、版本冲突、失败重试、驳回及重复驳回。驳回仍是原记录的状态，不应每点一次增加待复核样本；解释去向并合理跳转下一条。
5. 回原数据集：按可追溯来源与内容身份识别同图，人工修正替换相应标签，不重复加样本；原有划分保留。真正的新图才追加到指定集合。
6. 另建数据集：只包含所选有效反馈，划分 train／val／test；按身份分组避免同图跨划分泄漏，RGB／IR 配对保持一致。
7. 抽查导出后的真实图片、`labels`、`labels_ir`（适用时）、data.yaml 和 manifest；比较修改前后标签内容与样本数，不能只看数据库状态或成功提示。
8. 回流产物在 v1.7 项目绑定工作区内。原始文件与修订版本的关系按产品说明核对，不以任意覆盖源文件冒充修订。

**完成标准：** 画布、数据库、导出标签三者一致；同图修正不增样本，新图能追加；Agent 能读取来源与重复检查信息，并能操作回流业务。

- 同一会话至少连续三轮自然语言查询当前业务事实，含跨页和刷新；核对本轮确实查新数据，不靠用户额外说“重新查询”。分页数据必须按真实总数回答。

### 6.1 核验每条业务旅程时的固定做法

1. 先按新手实际任务走完一遍，记录点击、必填、重复确认、必须切页的次数及等待点。导航、筛选、选文件、提交分别计数；系统自动跳转不计人为点击，但仍记录用户是否丢失上下文。

| 高 | 模型导入 | 已上传／工作区权重选定后复用现有预检能力识别结构并填入 family、主辅模态、类别；避免“选权重→手动预检→重新选择同一权重→再选家族”。有进度与重试，预检结果复用必须匹配文件身份；类别映射仍不明确时才询问。 |
| 高 | 检测→AI核查→复核 | 从当前模型、选中数据集／样本继承上下文。一次明确的批量指令应串起检测、核查和打开待复核结果，不要求用户去三个页面重新选择同一批图片；保留单独检测、单独核查入口。权限和费用信息按既定模式处理，不擅自改变范围或权限。 |
| 高 | 记录批量操作 | 同一处选择记录后可批量核查、加入反馈、删除；操作完成保留筛选、分页和有效选择，不要求去详情逐条操作或重新勾选。显示实际处理数量与部分失败，不把当前页全选伪装成全库全选。 |
| 高 | 连续人工复核 | 同页完成画布操作和保存／提交；提交成功后进入同一队列下一项或明确完成态，不要求每张返回列表再打开。保留上一项／下一项、筛选与返回位置，未保存草稿离开时保护数据。驳回幂等，不重复产生工作量。人工结论由人作出。 |
| 高 | 复核后回流 | 从当前批次或已选反馈直接进入同一个回流操作区，自动带入来源集、样本身份和现有划分。只保留“回原修订／另建数据集”这个必要去向决策；在同一区域设置、预览、执行，不强迫用户在反馈池、候选草稿、数据集列表之间往返。草稿保留能力，但不要把每个内部阶段变成必须访问的页面。 |
| 中 | Agent 跨页协作 | 跳转业务页时保留当前项目、会话、任务与选中记录的必要上下文；导航工具打开的页面与 Agent 宣称的目标一致。用户能直接说“核查这些／处理这批”，无需复制 ID、路径或再次讲述上一页选择。最终事实须实时查询。 |
| 中 | 查看详情与返回 | 能在当前列表展开或侧区查看的轻量详情，优先不跳整页；真正的编辑页保留。返回时保留搜索、筛选、页码、滚动位置和未提交输入，不新增多层弹窗替代页面切换。 |
| 中 | 加载与失败重试 | 原地显示进度／错误和单次重试，不让用户靠刷新整页恢复，也不清空已选文件、参数或草稿。公共入口慢时明确区分上传、校验、推理、排队，避免伪装成“没反应”。 |

### 6.3 不允许以简化为名削弱的功能

- 不删人工上传、人工业务入口、细粒度单条操作或 Agent 对应能力；高级配置折叠后仍可找到。
- 保留业务主区域和右侧对话、现有认可的风格；不新做复杂首页、向导系统或平行设置页。
- 不用大量快捷按钮、重复卡片或新弹窗挤满每页；同一上下文最多一个清楚的主要动作，次要动作收敛但可发现。
- 不把“少确认”变成默认改变数据去向、覆盖文件、训练、发布或扩大批量范围；遵守用户当前权限模式与明确指令。
- 不绕过工作区授权、文件校验、版本冲突处理、人工核查结论或必要防误触保护。

### 6.4 交付与审查

在现有核验报告增加“已实施的操作简化”表：任务、原步骤、新步骤、减少的点击／必填／切页、涉及文件、人工入口保留情况、普通账号 UI 与 Agent 重测证据。高优先级旅程均需实际检查，其中确有冗余的要在本轮修复。较大取舍交 Codex 审查；不把全部未做项目留成用户自行规划的清单。

### 6.5 Computer Use 新增实证：控件必须有明确用途

2026-11-08 晚，Codex 在真实 WorkBuddy 普通账号页面复现以下两项，纳入当前修复与回归，不得被此前的阶段完成报告覆盖：

- **记录表格错位：** 操作列 td 的实际 `display=flex`、高度 42.67px，其余 td 为 `table-cell`、高度约 56.71／58.99px，底边相差 14～16px。恢复单元格表格语义，按钮排列放入内部容器；同时检查同类表格和窄业务区域。
- **复核勾选无完整用途、Agent 不知选择：** 队列勾选 `det_835255d9869e8dec` 后只有“已选 1 条”，无批量／清空入口。不透露 ID 的只读提问“我刚刚在当前人工复核队列勾选了哪条记录？请准确说出选中记录的 ID 和文件名”得到“工具不包含界面勾选状态”的回答，无法识别。

决定：保留有用的选择能力并补齐其业务连接，不保留仅显示计数的装饰性交互。复核与记录页选择需将页面、项目、精确记录 ID 和必要显示信息带入消息发送快照；后端验证归属与权限，Agent 能正确理解“这条／这些／所选记录”，不得猜测。提供清楚的已选上下文、清空与批量操作；批量开始复核只创建所选范围的导航队列，不自动作出人工结论。

**普通发送即生效是主路径：** 勾选后直接在右侧现有会话提问，Agent 应收到已校验的选择快照。不能必须点击“交给助手”、创建新会话或跳转整页后才生效。可选助手快捷入口只聚焦当前对话或附加可见选择提示，不无条件创建会话、发送未指定任务。选择上下文是对象范围数据，不是提高权限或允许模型执行其他操作的指令。

必须测单选、多选、清空、筛选、跨页／跨项目、对象删除后的选择有效性；未显式带入新页面的选择不得隐藏残留。复核列表以文件名、可读本地时间为主，长 ID 放辅助信息，压缩大块批次区域。审查其余前端控件是否产生明确业务结果、传递有效上下文或提供必要信息；重复或无效控件应合并、修通或移除，给出真实操作证据。
