## 3. 没验过的（不要当成已完成）

1. **启动器整文件没有执行**：工具层拒绝 `cmd.exe`，按要求没有换方式绕过，也没有启动任何公网连接器。
   退出码语义只有静态断言（失败分支经 `:failed` 返回 `%HX17_EXIT%`），实际双击行为需人工确认。
2. **没有重新发布**云端应用；`web/` 与线上那份相同，不等于“已经上传”。
3. **Cloudflare 未实测**：Zone 是否 Active、Tunnel、DNS、边缘对变形路径的处理都没有结果。
4. **512 MiB 上传**只做到 64 MB 端到端；更大体积未跑。
5. **没有起第二个连接器**，所以“整合后的目录能否连上现有云端”只证明了源码与令牌字节一致。

## 4. 这批没修的 5 个前端待办

审阅结论在 `项目资料/WorkBuddy平台版_方案A_20261107/前端待优化核对_20261108.md`，本批**没有动**它们：

1. 数据集「重新划分」点一下就执行，固定 `even/seed=7`、无预览无确认，且每次点击都复制出一份新数据集（v1.6 有比例表单 + 数量预览）。
2. 人工复核队列的勾选框没有任何批量动作；列表 `limit=100` 而计数按全量显示，没有分页或“还有 N 条”。
3. 数据集「样本」弹窗最多 200 条且不提示；接口失败与“没有样本”共用同一空状态，也没有重试。
4. 数据回流没有全选；「检查重复/跨划分泄漏」在“另建”模式下永远灰且无原因；切模式后仍可能指向被隐藏的旧父数据集。
5. 模型导入默认 `yolomm + IR`，单模态 `.pt` 必然先失败一次；「保存备注」在未改动时静默无反应。

这些是**已知缺陷**，不是“功能全无问题”。修它们要单独一轮，且要避免和其他执行者同时改同一批文件。
