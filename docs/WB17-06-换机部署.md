> 目标仓库与分支以 root 最终核验为准；**`workbuddy/haixun-v1.7.0` 在 root 验收并 push
> 之前并不存在于远端**，不要提前 clone。
>
> 本文所有命令都标了 shell：`powershell` 指 **Windows PowerShell 5.1**（系统自带那个），

> 所以下面的多步都写成一行一条；`cmd` 里才是 `set VAR=值`。

## 1. 依赖（按服务器环境选，不要照搬开发机）

- Python 3.10+（建议 3.11+；本机实测 3.14.6）。用**项目独立 venv**，不要升级机器上原有的
  YOLO/torch 环境。
- Node 22.6+（只在准备/构建阶段需要；**运行服务不需要 Node**）。

最简单的方式是双击 **`准备运行环境.cmd`**（装后端依赖 + `npm install` + `npm run build`）。
命令行等价写法（PowerShell 5.1，一行一条）：

```powershell
python -m venv .venv
.venv\Scripts\python -m pip install -r backend\requirements.txt
cd frontend
npm install --no-audit --no-fund
npm run build
cd ..
```

`cmd` 里同样可用（也是一行一条，`cd` 之后同一窗口继续）：

```cmd
python -m venv .venv
.venv\Scripts\python -m pip install -r backend\requirements.txt
cd frontend
npm install --no-audit --no-fund
npm run build
cd ..
```

- 如果 `python` 不在 PATH（`python -V` 报“不是内部或外部命令”），先用 `py -3 -m venv .venv`
  或写全解释器路径建 venv；建好之后所有命令都用 `.venv\Scripts\python`，不再依赖 PATH。

- 需要真实推理（检测/巡检/训练）时再装视觉依赖，**torch/torchvision 按本机 CUDA 驱动选
  wheel**（`torch>=2.6`，torchvision 与之配套）：

```powershell
.venv\Scripts\python -m pip install torch torchvision --index-url https://download.pytorch.org/whl/cu126
.venv\Scripts\python -m pip install -r backend\requirements-vision.txt
```

- 低于 torch 2.6 时服务端会显式报 `TORCH_TOO_OLD`（缺
  `get_unsafe_globals_in_checkpoint`），不要为兼容退回 `weights_only=False`。

- **注意：双模态（YOLOMM）链路在导入 vendor ultralytics 时就会 `import pytorch_grad_cam`**
  （`backend/vendor/ultralytics/models/yolo/multimodal/visualize/heatmap.py`），所以
  `grad-cam` 及其依赖是视觉依赖的必需项，不是只有画热力图才用。`backend/requirements-vision.txt`
  已列出；如果 `pip install -r` 在 `grad-cam` 处因缺少构建工具失败（Windows 常见），
  单独装一次（`--no-deps` 是为了不让依赖解析器顺手换掉已装好的 torch）：

```powershell
.venv\Scripts\python -m pip install --no-deps grad-cam ttach scikit-learn joblib threadpoolctl cloudpickle narwhals
```

  - `grad-cam` 声明 `opencv-python-headless`；本项目用 `opencv-python`（同一个 `cv2`），
    二者装其一即可，**不要**再装 headless 版造成两份 cv2 冲突。
  - 若 pip 缓存目录不可写（`WinError 5 拒绝访问` 指向 `AppData\Local\pip\cache`），
    先把缓存指到可写目录再装，例如
    `$env:PIP_CACHE_DIR='D:\tmp\pip-cache'`（PowerShell）或 `set PIP_CACHE_DIR=D:\tmp\pip-cache`（cmd）。

- **双模态训练还要求 `albumentations`**（vendor 的 `MultiModalAlbumentations` 在构造训练
  数据管线时要求 `albumentations>=1.0.3`）。缺少时训练子进程会明确失败：
  `TRAINING_ERROR: ImportError: MultiModalAlbumentations requires 'albumentations>=1.0.3'`。
  `albumentations` 声明 `opencv-python-headless`，直接 `pip install albumentations` 会在服务
  运行中尝试覆盖 `cv2.pyd` 并报 `WinError 5`；按下面方式单独装（保留已有 `opencv-python`、
  `simsimd`、`stringzilla`，不动 torch）：

```powershell
.venv\Scripts\python -m pip install --no-deps albumentations==2.0.8 albucore==0.0.24
```

  - 开发机 2026-11-07 真实训练实测版本：`albumentations 2.0.8 / albucore 0.0.24 /
    simsimd 6.5.16 / stringzilla 5.3.2 / torch 2.13.0+cu126 / torchvision 0.28.0+cu126`。
  - 装完可用 `.venv\Scripts\python -c "import albumentations, torch; print(albumentations.__version__, torch.__version__, torch.cuda.is_available())"` 自检。
- **AMP 默认关闭，正常训练不联网**：worker 只在显式设置 `HX17_TRAINING_AMP=1` 时才向
  vendor 传 `amp=True`；此时 vendor 的 `check_amp()` 首次会在线下载 5.35MB 的 `yolo11n.pt`
  基准权重做 CUDA AMP 校验，文件落在本次 `run_dir/` 内。离线机器应保持默认（不设该变量），
  不要为了“验证 AMP”而让训练依赖隐式联网；下载或校验失败时 vendor 会自动关闭 AMP，
  worker 不会把失败写成“AMP 通过”。

### 视觉依赖自检

装完先跑这条，不要等到网页里导入权重才发现缺包：

```powershell
.venv\Scripts\python -c "import tempfile, pathlib; from backend import config; from backend.vision import runtime; runtime.configure(config.load_settings(data_dir=pathlib.Path(tempfile.mkdtemp())/'private', serve_dist=False)); print('ACTIVATE_OK', runtime.activate_vendor())"
```

- 成功输出 `ACTIVATE_OK ...backend\vendor\ultralytics\__init__.py`。
- 失败时服务端报 `VISION_DEPENDENCY_MISSING`，但界面消息只有异常类型名（如
  `ModuleNotFoundError`），**具体缺哪个模块看这条命令 traceback 的最后一行**
  （`ModuleNotFoundError: No module named 'xxx'`），按名字补进 requirements-vision。
- 首次导入（加载 torch + vendor 网络结构）约 12–20 秒，属正常。

## 2. OpenCode 引擎（对话功能）

- 安装 OpenCode **1.19.4**（启动时严格校验版本，不匹配拒绝启动）。
- 把 `opencode.exe` 放进 PATH，或者用环境变量指过去。**两种生效范围不同**：

```powershell
# 只对当前这个 PowerShell 窗口生效（复制完就能用，关窗口即失效）
$env:HX17_ENGINE_EXE = 'D:\tools\opencode\bin\opencode.exe'

# 永久写进用户环境变量：只影响**之后新开**的进程/窗口，当前窗口读不到
setx HX17_ENGINE_EXE "D:\tools\opencode\bin\opencode.exe"
# 所以 setx 之后要关掉重开一个终端（或重新双击启动海巡智检.cmd）才会生效
```

- 不配置时网站仍可启动、页面功能正常；发起对话会明确报 `ENGINE_MISSING`。
- 不要从不可信目录随手捡一个同名 exe——版本闸门会拦版本，但路径本身要你来保证。

## 4. 单端口启动 / 健康 / 停止

启动（默认 `127.0.0.1:8080`；可加 `--port`/`--data-dir`，或设 `HX17_PORT`/`HX17_DATA_DIR`）：

```powershell
# 从 PowerShell 调当前目录里的 .cmd 必须带 .\ ，裸文件名会报“找不到命令”
.\启动海巡智检.cmd

# 换端口 + 中文带空格的数据目录（当前窗口直接生效）
.\启动海巡智检.cmd --port 9000 --data-dir "D:\海巡数据 v17"

# 健康检查：用 curl.exe，否则 5.1 里的 curl 是 Invoke-WebRequest 的别名
curl.exe -s http://127.0.0.1:8080/api/health
# 等价写法：Invoke-RestMethod http://127.0.0.1:8080/api/health
```

```cmd
:: cmd 里不需要 .\ 前缀，设置变量用 set
启动海巡智检.cmd
启动海巡智检.cmd --port 9000 --data-dir "D:\海巡数据 v17"
curl.exe -s http://127.0.0.1:8080/api/health
```

- 重复启动同一数据目录会提示“已在运行”，PID 不变，不会起第二个实例。
- 端口被陌生程序占用时只报错退出（退出码 5），**不结束任何进程**。
- 运行记录里的 PID 还活着但服务不响应时也会拒绝启动（退出码 6）——同一目录起第二个实例会
  争用同一份数据库、把对方正在跑的轮次标成中断；确认那个进程已不是本服务后，删掉
  `<数据目录>\run\server.json` 再启动。
- 把别的数据目录的 `run\server.json` 拷进来不算“已在运行”：`--status` 报身份不一致
  （退出码 4），`--start` 直接拒绝，不会把别人的实例当成自己的。

正常停止（只停“运行记录里自报身份一致”的那个实例）：

```powershell
.\停止海巡智检.cmd
```

有进行中的对话/业务/训练时会**拒绝**并说明原因（退出码 9 或 10）；确认要中断它们才强停：

```powershell
# 显式强停：还在跑的对话轮次会在重启后被标记为中断，正在训练的子进程也会被终止。
# 只在确认这些工作可以丢弃时使用，不要把它当默认操作。
.\停止海巡智检.cmd --force
```

命令行等价：

```powershell
.venv\Scripts\python deploy\serve.py --check
.venv\Scripts\python deploy\serve.py start --port 8080
.venv\Scripts\python deploy\serve.py --status
.venv\Scripts\python deploy\serve.py --stop
.venv\Scripts\python deploy\serve.py --stop --force
```

`--stop` 的退出码含义（脚本化判断用）：`0` 已停止；`4` 记录属于别的数据目录或同目录已有
实例；`6` 记录里的 PID 还活着但服务无响应（需人工确认）；`8` 请求已发出但没收到确认；
`9` 还有进行中的任务；`10` 读不到任务状态（数据库损坏/被独占，**不会自动修库**）。

## 5. 备份与恢复（两种场景，别混）

**A. 同一台机器冷备/还原**：备份范围是两块，缺一不可。

```powershell
# 1) 运行数据目录（HX17_DATA_DIR，默认 <工程>\var）：haixun.db、secrets\、run\、
#    引擎隔离目录——账号、口令哈希、加密密钥、运行记录都在这里。
dir var

# 2) 项目绑定目录：数据集、原图、权重、回流产物、训练输出都在这里（不在 var 里）。
#    backend.cli list-roots 可以看到每台机器授权过的根目录。
.venv\Scripts\python -m backend.cli list-roots
```

- 业务产物按用途放在**项目绑定目录**（`projects.root_path`，即授权根下的那个项目文件夹）里的
  `uploads\`（原始字节）、`artifacts\`（检测结果图/可视化）、`datasets\`（导入副本 +
  `data.yaml`）、`training\`（训练输出）、`.cache\`（可重建的中间件）。
  所以“只备份 `var\`”只保住了数据库、密钥和运行记录；**冷备必须把数据目录和项目绑定目录
  一起备**（前者给服务用，后者是业务文件）。
- **不要**为了方便把数据目录和工作区合并、或搬动已有文件去迁就文档：两者的边界是生产
  安全边界（服务端私有区 vs 用户授权区）。要迁移就走“备份 → 还原/重新授权”的流程。
- `.cache\` 是可重建的，赶时间可以跳；`uploads\` / `datasets\` / `training\` 不能跳。

**B. 换一台新机器部署**：这是“新部署”，不是“恢复旧机器”。

- 新机器自己生成数据库、`secrets\` 与账号（第 3 节重新建号），自己填个人模型连接。
- **不要**把开发/QA 机器的 `haixun.db`、`secrets\`、验收账号拷过去覆盖：密钥与账号必须
  各自独立，旧库还会把开发期的测试数据带进交付环境。
- 换机更新代码：`git pull` → 重跑“准备运行环境” → 启动。更新前先按场景 A 备份**本机自己的**
  数据目录与工作区。

## 6. 可选：Cloudflare 受控入口

- 需要**你自己的**域名与 Cloudflare 账号：把域名接入 Cloudflare → 建一条指向这台机器的
  隧道/回源规则 → 后端设 `HX17_COOKIE_SECURE=1`。
- 临时 `*.trycloudflare.com` 地址随时会变，**不是**永久稳定入口，不要写进交付材料。
- 本项目不代买域名/服务、不改 DNS；没有外网入口时全部功能在 `127.0.0.1` 可用。
- 启停管理接口（`/api/service/*`）不要暴露到公网：它只靠“随机令牌 + 回环地址 +
  拒绝转发头”保护，不是面向公网的认证方案。

## 7. 部署后自检

`backend/requirements.txt` 是**运行期**依赖，**不含 pytest**；自检用标准库 `unittest` 就够，
不需要为跑测试额外装框架。

```powershell
# 1) 环境与产物：依赖、Waitress、frontend\dist、数据目录可写
.venv\Scripts\python deploy\serve.py --check

# 2) 真实启停冒烟（起真服务 → 健康/静态/深链 → 重复启动 → 身份校验 → 忙任务拒停 → 正常停止）
.venv\Scripts\python scripts\deploy_smoke.py --python .venv\Scripts\python.exe

# 3) 完整非训练回归（标准库 discover，约几分钟；真实微训练用例默认跳过）
.venv\Scripts\python -m unittest discover -s backend/tests -t .
```

真实 1 epoch CPU 微训练是**显式 opt-in**，默认不跑（会真的起训练子进程，约 1–3 分钟）：

```powershell
$env:HX17_RUN_REAL_TRAINING_TEST = '1'
.venv\Scripts\python -m unittest backend.tests.test_business_wb17_05_training.TrainingRealWorkerTest.test_real_worker_end_to_end_registers_publishes_and_resolves_labels
Remove-Item Env:\HX17_RUN_REAL_TRAINING_TEST
```

如果你自己的机器上已经有 pytest，也可以照原来的方式跑（`python -m pytest backend/tests -q`），
但那是可选工具，不是部署前提。

任何一步失败先看提示（缺依赖/未构建/端口占用都有明确指引），不要删 `var\` 来“重置”。
